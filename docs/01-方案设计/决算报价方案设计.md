## 1. 需求背景与拍板记录

### 1.1 需求

装修决算(decorationaccount)希望增加一个**决算报价**的概念:

- **不建立后台与数据结构**:零新表、零新 PO/VO、零新 .do 接口;
- **利用报价项/扩展项/增减单进行归档**:决算报价的内容 = 默认报价 + 报价扩展 + 增减单三类既有数据实时归组,归档依托现有 `decorationaccount` / `decorationaccountitem` 结构;
- **显示报价/增减/扩展的相关数据**并利用 `decoration4account.html/js` 中既有的计算公式(`accountSuper()`)计算决算金额;
- **提供其中部分功能用于重新计算决算金额**(折扣输入重算、算/不算配比、配比方案切换等);
- 展示角度调整为**功能区 → 项目**两级方式;
- 新页面命名为 **`auotationPart.html/js`**,放在**报价模块**(account决算 + quotationPart 合成词,可理解为"报价中的决算")。

### 1.2 拍板记录(2026-11-12)

| 决策点 | 拍板 |
|---|---|
| 页面命名 | `auotationPart.html/js`,**非笔误**,= account(决算) + quotationPart,放 `views/quotation/` + `js/quotation/` |
| 入口形态 | 决算计算页(decoration4account)顶部加"决算报价"按钮,`com.popup4page` 近全屏弹窗打开 |

### 2.2 `accountSuper()` 公式全集(decoration4account.js L1405-1531,注释原文 L1407-1435)

记:`flag = 算配比 ? 1 : 0`(`arcal==0` 为算配比,L1439);`dd = 决算折扣`(可由重算输入框覆盖,L1441-1444);`_managePrice = 管理费 × (manageDiscount==1 ? dd/10 : 1)`;`_taxPrice` 同理受 `taxDiscount∈{1,2}` 控制。

| 输出 | 公式 | 落库字段 |
|---|---|---|
| 决算直接费 beforeTotal | 打折总额 + 不打折总额 + 车运费 + 增项配比总额×flag − 减项配比总额×flag | projectBase |
| 决算管理费 management | 管理费 + 增项管理费×flag − 减项管理费×flag | — |
| 决算税金 taxment | _taxPrice + 增项税金×flag − 减项税金×flag | — |
| 决算合同额 contartval(半包0/整装1) | (打折总额+增/减打折配比×flag)×dd/10 + (不打折总额+增/减不打折配比×flag) + 车运费 + _managePrice + 增/减管理费×flag + _taxPrice + 增/减税金×flag | —(仅展示) |
| 决算合同额 contartval(满减2) | (beforeTotal − beforeTotal%折扣基数)×折扣/10 + beforeTotal%折扣基数 + 管理费族 + 税金族(同上) | — |
| 决算服务费 service | (beforeTotal + 管理费 + 增/减管理费( predis )×flag + 税金 + 增/减税金(predis)×flag) × 主材配比 × 服务费比例 | servicePrice |
| 决算主材额 materialAccount | direct × 主材配比;**已有决算记录或手动维护时用输入值**(L1493-1497) | materialPrice |
| 差额(不含预付款) balanceSum | contartval + service − 合同实收 − 已收服务费 − 增项总额×flag + 减项总额×flag + 增项非配比×flag − 优惠 − 内部券 − 满送 − 返现 | difference |
| 实花配比 flowerRatio | 主材实收合计 / direct | paidupMatching |
| 实花配比(含外销) flowerOalesRatio | (外销配比总额 + 主材实收合计) / direct | — |
| 决算折前总额全 directC | 报价折前总价 + 增项折前(扩展) − 减项折前(扩展) + 增项折前(增减) − 减项折前(增减) | — |
| 应补款 fullPayment | 合同未收 + 增项未收 − 减项未收 | — |
| 金额差 difference | 主材实收额 − 决算主材额 | — |
| 超配比 superRatio | 金额差 / 决算主材额 | — |

> 注:saveDecorationAccount 时 `projectPrice = direct`(决算折前总额,L813)、`projectBase = beforeTotal`(L814)。

### 2.4 增减单决算口径细则(queryAddReduce L1201-1331)

- 单级过滤:`paytype == 0`(PAYTYPE_PAY)且 `status ∈ {2,3}`(已付款/已确认),其余单**不参与计算**;
- 折扣回退链:`accountDiscount==0 → (discount==0 → 决算折扣 dd)`,manage/tax 同款(L1209-1211);
- `managePrice = accountManageDiscount==1 ? 单管理费×accountDiscount/10 : 单管理费`;tax 同款;`totalPrice = calPrice×accountDiscount/10 + uncalPrice + managePrice + taxPrice`(L1213-1215);
- item 级折扣归属(L1320-1331):`addreduceitem.discount==1 → addDisCalPrice/reduceDisCalPrice(打折配比)`,`==0 → addUndisCalPrice/reduceUndisCalPrice(不打折配比)`,金额 = unitPrice × num;
- atttype 细分:0=施工增减族、1=主材增减族(两套聚合,决算主公式用全量族)。

### 2.5 现有"重新计算"功能(新页面移植来源)

### 2.6 现有归档机制

## 3. 决算报价概念定义与数据口径

### 3.1 定义

**决算报价 = 以"报价 + 扩展 + 增减"三源数据按功能区归组形成的虚拟报价单**,是决算金额计算的明细底稿:

```
决算报价(虚拟,不落新表)
├── 报价源:默认报价 quotationfunctionarea × quotationfunctionareaitemN(按功能区 index 分表,接口已组装)
├── 扩展源:extension × extensionitem(item 挂 quotationFunctionAreaId → 可归功能区)
└── 增减源:addreduce × addreduceitem(item 同样挂 qfaId;决算口径单标"计入",其余标"不计入")
        ↓ 按 key = qfaId + '-' + 功能区名 归组;无归属进"-扩展项目"/"-增减项目"桶
        ↓ 项目行小计 = unitPrice × num,增减行按 accountDiscount 回退链折算
    → 汇总出打折项/不打折项/管理费/税金族 → 喂入 accountSuper() 公式 → 决算金额
        → 保存:decorationaccount(主记录)+ decorationaccountitem(明细快照,新增功能区行组)
```

### 3.2 口径约定

| 项 | 口径 | 依据 |
|---|---|---|
| 报价源 | 默认报价(defaults),功能区 type∈{1工程量,7综合}计入打折/不打折汇总 | quotationUtils L146-149 同款 |
| 扩展源 | 全量展示;**金额仅进"折前总额全(directC)",不进主公式**——与现决算页一致(L456-537 仅展示,L1489 directC 引用),页面明确标注该口径 | 决算页现状 |
| 增减源 | 全量展示,**仅 paytype=0 且 status∈{2,3} 的单参与决算计算**,行标"增减-已付款(计入)/增减-未付款(不计入)" | L1203-1207 |
| 金额单位 | api tranargs 已换算为元,页面内部一律 `utils.accAdd/accSub/accMul/accDiv`,展示 `Math.round` 元 | core.js L210-259 |
| 扩展/增减行折扣 | 增减行按 accountDiscount 回退链折算(2.4 节);扩展行沿用决算页口径(减项单价取负 × 折扣/10,见 quotationUtils L470-477) | 2.4 节 |

### 3.3 归组实现取舍

参照 `quotationUtils.statisticalQuotationItem`(quotationUtils.js L95,归组键构造 L438/L497-503,桶定义 L443-445,suptype 1报价/2扩展/3增减 L479)的**归组思想**,但**不复用其渲染链**(`initQuotationDetailItem`/`initQuotationFunctionAreaDetail`):该链面向报价编辑/详情页,dcp/dcpt 折扣展示口径与决算页 `unitPrice×num + accountDiscount` 口径不同,强复用会口径混叠。新页面在 `auotationPart.js` 内实现轻量只读归组 painter(参照 quotationPart.js painter 结构,但去除全部编辑能力)。

### 4.2 交互要点

- **打开**:继承宿主页全局 `params`(orderId 已在),无需传参;`com.popup4page` 同窗口 `_holder.load(url)`(core.js L1502),`api`/`constant` 直接可用;

- **未建档单**:②③⑤正常展示+④可重算预览,**保存置灰**,提示"请先在决算计算页生成决算记录"(避免 name/type/typeness 空值落库)。

## 7. 边界、并发与权限

### 7.1 数据边界

- **无默认报价**:`queryQuotationForDefaultByOrderId` 返回空 → 弹窗提示"默认报价不存在"并止步(同 quotationUtils L25-28 行为);

- **满减单(type==2)**:折扣基数 base 取自决算记录 `discountBase`(applyDecorationAccount L757),未建档时只读;
- **分表透明**:quotationfunctionareaitemN 按功能区 index 分表由接口组装,前端无感;
- **金额精度**:一律 api tranargs 换算 + `utils.acc*`,禁手写 ×1000/÷1000(既有 feedback 铁律)。

### 7.2 并发

弹窗内保存与决算计算页操作**同一 decorationaccount 主记录**,存在双人并行编辑覆盖风险。采取轻对策(与决算页自身现状一致,决算页保存本就整行覆盖):

1. 保存前 confirm 明示"将覆盖现有决算记录";
2. 保存成功后弹窗内回读刷新;宿主决算页数据可能陈旧,按钮提示用户关闭弹窗后刷新决算页;
3. 重型对策(保存前回读比对 discount/materialPrice 冲突检测)列为 9.2 待拍板,本期不做。

### 7.3 权限

- 弹窗按钮与"决算"按钮同位同权:可见性随 `pageBtn.contains("cal")`(决算按钮档位),不新增权限点;
