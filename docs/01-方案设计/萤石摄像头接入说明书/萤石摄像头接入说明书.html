Camera Integration Brief

萤石摄像头接入说明书

A4 说明文档
管理决策版
2026-08-21
把摄像头接入定义为工地视频资源服务，第一阶段先跑通直播、抓图与图片集播放，真实视频生成只放在竣工交付、分享传播和证据归档等重场景。
核心原则：后台负责设备绑定、抓图、存储、授权和素材组织；前台负责图片集播放体验；视频生成作为按需增强能力。

一页看懂：先轻后重的接入边界

客户看什么

实时直播、今日快看、节点影集、全部图片。客户日常最关心现场是否变化，不必默认生成 MP4。

后台管什么

绑定设备、配置客户可见时间、主动抓图、图片审核、在线巡检、访问日志。

系统怎么接

后端代理萤石接口，统一管理 accessToken、设备通道、播放地址、抓图结果和权限校验。

后续扩什么

节点自动影集、回放、事件告警、竣工视频、多厂商适配和施工日报。

01

绑定摄像头

按装修单 orderId / 施工单 cid 绑定 deviceSerial 与 channelNo。

02

生成临时地址

客户请求直播时后端校验权限，再向萤石换取播放 URL。

03

抓图入库

客户、内部人员、节点事件或定时任务触发抓图，转存 OSS。

04

前台播放

图片太多时按时间均匀抽取，形成可播放图片集。

Objective

业务目标与系统落点

02
客户侧目标

客户希望快速知道现场是否施工、今天是否有变化、当前节点是否推进、问题是否可以留证。日常使用更偏“快速确认”，不是持续盯直播。

内部管理目标

远程巡检、节点图片留档、客户反馈证据补充、摄像头在线巡检，以及后续施工日报、工地日历、竣工视频。

产品边界：第一阶段不做完整视频生产平台，先跑通“摄像头绑定 -> 授权观看 -> 抓图入库 -> 图片集展示 -> 前台播放”。

萤石接入链路与目标架构

03
Client
客户侧 H5 / 小程序展示直播、今日快看、节点影集、图片集播放和问题反馈。前端不接触厂商凭证。
关注播放协议和小程序合法域名。
ERP
Rhadamanthus 摄像头业务接口校验客户与订单关系，控制可见时间，组织播放序列，记录直播、抓图、分享访问日志。
权限必须在后端完成。
Provider
CameraProvider 厂商适配层封装 accessToken、直播地址、抓图、回放和在线状态查询。业务层不直接依赖萤石字段。
预留多厂商 provider。
YS7
萤石开放平台按 appKey/appSecret 获取 accessToken，再基于 deviceSerial + channelNo 获取直播、抓图、回放能力。
上线前核对账号权限与套餐。
后端必须代理厂商接口：appSecret、accessToken、设备验证码、长期播放地址都不应暴露到客户前端。客户前端只拿短时有效的播放 URL 或系统授权后的图片地址。

推荐调用方式

01

客户请求

携带 orderId、cameraId 进入直播或影集页面。

02

后端校验

校验客户身份、订单关系、可见时间和能力开关。

03

厂商调用

刷新或读取 accessToken，调用直播、抓图或回放接口。

04

返回内容

返回临时 URL、图片列表或播放序列，并写访问日志。

第一阶段接口

接口用途处理重点
queryConstructionCameraByOrderId.do查询订单摄像头列表。后台/客户侧都可使用，但返回字段应按权限裁剪。
queryConstructionCameraLiveUrl.do获取直播播放地址。校验客户与订单关系、openLive、可见时间段，再向萤石换取临时 URL。
captureConstructionCamera.do主动或事件触发抓图。按 triggerType 记录来源，客户触发必须限流，关键图片转存 OSS。
queryConstructionCameraMedia.do查询图片集。按日期、节点、摄像头、可见性筛选。
queryConstructionCameraPlayList.do返回前台可播放图片序列。图片太多时后端按时间均匀抽取精选序列。
Rhadamanthus · Construction Camera04 / Data & API
Capture

抓图触发与留档策略

05
客户主动触发

点击“刷新现场图片”“保存当前画面”或提交问题反馈时触发。必须按客户、摄像头、订单做 30-60 秒限流，并设置每日上限。

内部人员触发

监理、项目经理、质检远程巡检时主动抓图。可少受客户限流影响，但必须完整记录操作日志。

施工节点触发

节点开工、完工、验收、返工开始、返工完成时自动抓图。属于高价值资料，建议长期保存并挂到施工图片。

定时或告警触发

定时抓图形成施工日报和工地日历。设备离线、上线、遮挡、移动侦测可作为内部告警，默认不直接推给客户。

统一抓图服务

triggerType说明建议处理
customer客户主动刷新/反馈截图。限流、校验可见时间、可绑定反馈记录。
user内部人员主动抓图。记录操作者，可归档为巡检资料。
node施工节点事件触发。长期保存，同步施工图片。
schedule定时任务抓图。普通图片可设置 30/60/90 天保留。
alarm设备事件或告警触发。默认内部可见，避免误报和隐私争议。
定时抓图建议从每天 4 次开始：09:00、11:30、14:00、17:00。不要高频抓图，避免接口频率、存储成本和隐私压力过早放大。
Rhadamanthus · Construction Camera05 / Capture Strategy
Album First

图片集播放优先，视频按需生成

06
日常客户感知不需要默认生成视频。图片集加前台自动播放已经足够轻、快、可控；真正的视频生成留给竣工、分享、宣传、证据归档等高价值场景。
图片数量展示方式说明
0 张空状态提示“今日暂无现场图片”，避免误导客户。
1-2 张图片集不自动播放，只展示图片与拍摄时间。
3-12 张自动播放每张 1.5-2 秒，形成“今日快看”。
13-30 张全量或精选播放可降低停留时间，也可按时间段抽取。
30 张以上精选播放 + 全部图片后端按时间均匀抽取 12-20 张，其余进入完整图片集。
今日快看定时抓图后自动形成，客户打开即可看，不等待生成任务。
节点影集节点开工、完工、验收抓图，按施工阶段组织。
真实视频竣工交付、外部分享、宣传案例、争议证据再异步生成 MP4。

视频生成边界

模板图片数量时长场景
日报视频4-8 张8-15 秒每日工地回顾，后续可选。
节点视频10-30 张15-45 秒节点交付或客户通知。
全周期视频每节点 5-10 张60-120 秒竣工交付和客户分享。
异常视频事件前后若干张10-20 秒争议、投诉或告警留证。

Permission

权限、隐私与运营控制

07

客户查看必须满足

身份有效客户已登录，或分享 token 有效且未过期。
订单匹配客户与 orderId 存在合法关系，不允许跨订单查看。
设备启用摄像头状态启用，且对应能力开关开启。
时间可见当前时间在 visibleStart 与 visibleEnd 范围内。
状态允许施工中可开通直播，竣工后默认关闭实时直播。
日志完整直播、抓图、影集、分享均记录访问日志。

敏感数据处理

数据风险处理方式
appSecret / accessToken暴露后可调用厂商接口。仅后端保存和使用，前端不返回。
设备序列号 / 验证码可定位设备和通道。验证码加密存储，序列号按权限裁剪返回。
播放地址长期外泄会绕过权限。短时有效，过期重新获取。
客户分享链接可能被转发扩散。设置有效期、访问次数和访问日志。
隐私策略：夜间默认关闭直播和抓图；告警图片默认内部可见；后台可隐藏不适合客户查看的图片；竣工后关闭实时直播，只保留历史资料。

Roadmap

分阶段实施与验收

08
阶段 1
基础闭环后台绑定摄像头，客户获取直播地址，客户/内部人员主动抓图，图片转存 OSS，访问日志完整记录。不做回放、视频生成、告警回调。
阶段 2
定时抓图与图片集播放定时任务生成今日图片，前台播放“今日快看”，图片太多时后端返回精选序列，后台可管理图片可见性。
阶段 3
施工节点影集节点开工、完工、验收触发抓图，节点图片归档到施工图片，节点完成后可生成客户通知。
阶段 4
回放与事件告警接入录像回放、最近 24 小时/7 天回放、萤石事件回调、离线提醒和内部告警图片。
阶段 5
视频生成竣工全周期视频、节点交付视频、投诉证据视频，使用异步任务生成 MP4 并上传 OSS。

第一阶段验收标准

客户侧

客户只能看到自己订单的摄像头；可获取直播地址并播放；可主动抓图且受限流控制；非可见时间段不能查看。

后台侧

可绑定设备、启停直播、配置可见时间、内部主动抓图归档；抓图入库并转存 OSS；访问日志完整。
