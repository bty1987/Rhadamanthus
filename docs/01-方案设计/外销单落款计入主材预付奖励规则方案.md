# 外销款并入主材预存奖励基数方案

> 2026-11-03 · v3(定案) · 状态: 待落码
>
> **修订记录**:
> - v1 否决: ①外销款不新增"落款"通道(oalespayment 不加 settle/预付款抵扣); ②不做独立的"落款每满"规则类型——外销款必须与主材预存合并为一份基数一起计算, 不是独立计算每满或阶梯。
> - v3 定案: ①外销退款**扣减**基数(采纳推荐, 与预存提现减对称); ②**去掉 `oales.isActivity` 判断**——外销款全量计入, 不按"参与活动"过滤, 无 updateOales 翻转桩。

---

## 1. 需求定案

外销单(`sales.oales`)的收款(外销款)计入主材预存净额, 与主材预付款收/提流水**合并为同一份基数**, 参与现有"预存每满/预存阶梯"奖励规则的计算。规则类型、规则配置、发放机制、前端动作**全部不变**; 无 DDL、无新 error 码——纯读侧并入 + 触发桩。

---

## 2. 代码事实

- **发放引擎**(唯一基数消费点): `DecorationActivityItemServiceImpl.issueDecorationActivityItemByOrderId` :775 —— `net = paymentDao.amountPayment(orderId, paymentType=2 主材预付款, 活动窗口)`(收款 type=1 加、提现 type=0 减, status∈{1,2}); 规则行按此基数算每满(floor(net/perAmount)×tickets 可封顶)与阶梯(net≥threshold)。
- **外销款数据形态**: `payment.oalespayment`(referMoney/status 0初始→1已付→2已确认/type 0收款·1退款/**自带 orderId 装修单归因列**, NOT NULL) ⋈ `payment.oalesreceipt`(collectTime 收款时间); 外销收款只走现金/银行/转账, **不产生 payment.payment 流水、不碰主材预付款余额**。
- **引擎触发桩现状**: 主材预存收款确认/提现/合同重签/合同终止 + 手工补发 Action; **外销款收款链未挂桩**。
- **段文本=回收锚**: 补发券 content 含规则段(如"预存主材款每满10000元赠1张"), 回收时按 content 与现存段匹配——段文本措辞动不得。

---

## 3. 设计: 一处并入 + 两处挂桩

### 3.1 基数合并(引擎一行并入)

```java
// 预存主材净额 = 活动窗口内收款(type=1) − 提现(type=0) + 外销款净额(收款−退款), 仅有效流水(DAO sum)
long net = paymentDao.amountPayment(orderId, PaymentPO.PAYMENT_PAYMENTTYPE_MATERIAL_INT, activityPO.getStartTime(), activityPO.getEndTime())
         + oalesPaymentDao.amountOalesPaymentForLottery(orderId, activityPO.getStartTime(), activityPO.getEndTime());
```

规则 2/3 的分支代码、perAmount/tickets/maxTickets 语义、补发/回收循环**全部原样**——外销款在 net 源头并入, 每满的 floor 语义、阶梯的一次过线判定都天然作用于合并基数(不是外销款单独算一遍再相加)。

**约束层级——外销款与主材预存同权, 全部经活动规则约束**(引擎闸门顺序: 查装修单 → 查活动 → 查规则 → 才求和):

- **公司维度**: 活动(`information.activity`)按公司配置, `queryActivityForLottery(company, now)` 只找**本公司**在窗有效抽奖活动——公司没配活动/活动过期停用, 引擎在求和前即 `return 0`, **外销款连查询都不发生**; 公司"参与"的方式 = 给它配活动行(双人海外玩翻天即每公司一个 aid: 3552/3554/…), 与主材预存今天被约束的方式完全相同;
- **窗口维度**: 活动 startTime/endTime 圈定外销收款归属(窗口锚 = oalesreceipt.collectTime);
- **规则维度**: 仅启用规则行参与(`queryActivityRuleForEnabled`, status=启用按 sort 排序), 且外销款只进 type=2 每满 / type=3 阶梯的基数——签约赠(type=1)不使用 net, 不受并入影响。

### 3.2 新 DAO 方法(payment 模块, OalesPaymentDao/Impl)

`amountOalesPaymentForLottery(String orderId, Timestamp startTime, Timestamp endTime)`(动词 amount + 对象本 DAO 实体 + ForLottery, 对齐 countDecorationActivityItemForLottery 先例):

```sql
SELECT SUM(CASE WHEN op.type = 0 THEN op.referMoney WHEN op.type = 1 THEN -op.referMoney ELSE 0 END)
FROM payment.oalespayment op
JOIN payment.oalesreceipt r ON op.orid = r.orid
WHERE op.orderId = :orderId
  AND op.status IN (1, 2)         -- 已付/已确认, 对齐主材预付口径
  AND r.collectTime >= :startTime AND r.collectTime <= :endTime
```

- 归因: `op.orderId`(装修单号, 表列 NOT NULL, 免 join sales.oales);
- 方向: 收款(type=0)加、退款(type=1)**减**(定案①, 与预存"提现减"对称, 防退款套券);
- 窗口锚 = `oalesreceipt.collectTime`(真实到账时刻; oalespayment.createTime 是建行时间, 收款可能滞后数日, 不可用);
- **无 isActivity 判断**(定案②), 不 join sales.oales。若日后要排废单, 加一行 join 条件 `o.status != 6` 即可, 当前不引入。

### 3.3 段文本铁律(回收安全)

- 规则段措辞**一个字不改**: 仍发"预存主材款每满X元赠Y张"——存量已发券的 content 锚匹配不受影响, 不会被误判孤儿回收;
- 仅发放 content 尾部摘要(非锚)扩展为"活动期内主材预存净额X元(含外销款Y元)", 便于事后对账读数。

### 3.4 触发桩(两处)

`OalesPaymentServiceImpl` 注入 decorationActivityItemService(同 PaymentServiceImpl 先例), 收退款后调 `issueDecorationActivityItemByOrderId(oalesPayment.getOrderId(), userId)`(orderId 空或引擎内无在窗活动时自识别返回 0):

| 桩点 | 时机 | 效果 |
|---|---|---|
| `collectOalesPayment` | 收款 status→1 后 | 基数上涨 → 补发 |
| `refundOalesPayment` | 退款 status→1 后 | 基数下降 → 回收未中奖券 |

confirmOalesPayment(1→2)不挂: 两个状态都计基数, 无基数变化。其余边角(废单等)靠手工补发入口(`issueDecorationActivityItem.do`)兜底。无 isActivity 翻转桩(定案②, 无该场景)。

## 6. 边界与验证

**边界**:
- 外销款不进 `payment.payment`、不扣主材预付款余额——主材预付**资金口径**零变化, 并入仅发生在活动基数读取侧;
- 签约赠(ruleType=1)不走 net, 不受影响;
- 未关联装修单的外销单不并入(oalespayment.orderId NOT NULL, 无从归因的行不存在);
- 同一笔钱不双算: 外销款是实收现金/银行, 主材预存是预付款流水, 两池天然不相交;
- 回收链闭环: 退款降基数 → 未中奖券失效; 已抽(11)/已领(10)不碰(既有铁律);
- 废单外销单若有已收未退款项, 基数暂计至退款发生(与主材预付不看装修单状态同口径), 需要收紧时再加 join 条件。

**验证要点**(erp-T):
- U1 外销单收款确认 → 券按"预存净额+外销款"合并基数补发, content 尾部含外销款摘要;
- U2 外销退款 → 券自动回收(未中奖置失效);
- U3 每满 floor 语义作用于合并基数(如预存 1.2 万+外销 0.9 万, 每满 1 万档 = 2 张而非 1+0);
- U4 回归: 无外销款装修单应得数不变; 老券不被误回收(段文本未动); 主材预付款余额与对账口径零变化;
- U5 窗口外收款不计(活动 startTime/endTime 边界)。
