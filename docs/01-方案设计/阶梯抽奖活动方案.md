# 阶梯抽奖活动方案（阶梯券降级发放）

> 模块：information（activity/activityrule/activityitem/awardstock）× decoration（decorationactivity/decorationactivityitem）
> 状态：方案稿——**核心机制已与用户对齐，下游业务调整待讨论后定稿实施**
> 日期：2026-11-07

---

## 一、需求与背景

阶梯抽奖活动：活动奖品按等级（一等奖/二等奖/三等奖…）配置**券**，等级间**可设优先级**；装修单参与活动时**先添加券信息**（预占），**签约时按奖品剩余数量结算发放**——优先级最高且有库存的等级先发，清零自动降级（一清零发二、二清零发三），全清零期间预占券保持初始态等待后续领取（库存可能因盘点/退回变化）。**每单发一张**。

与现有抽奖券引擎（type=20，规则行=签约赠/预存每满/阶梯预存，应得数对齐+自动回收）**平行独立**：新活动 type=30、新券 type=30、新规则行 ruleType=5（阶梯奖品行），不复用现有规则行语义。

## 二、决策记录（已拍板）

| # | 决策 | 说明 |
| --- | --- | --- |
| 1 | 券类型新增 **type=30**（`DecorationActivityItemPO.TYPE_LADDER_LOTTERY_INT`） | 不进券族 `TYPE_COUPON_FAMILY={0,10,20}`、不进 couponCut/thingCut 金额口径；atttype=0（不参与 banch 线上核销）、isPrefor=1（不计业绩）、isPayment=1；**money=配置面值**（参与收款配比，见销售收款券配比方案） |
| 2 | 活动类型新增 **activity.type=30**（`ActivityPO.TYPE_LADDER_LOTTERY_INT`） | 引擎按 `company + 窗口(startTime/endTime) + type=30` 定位活动，照 `queryActivityForLottery(company, now)` 模式；活动为**公司级别** |
| 3 | 剩余数量=**`awardstock.num` 直读** | 同奖品可多活动混用（按场景接受）；扣减沿 receive 链同款守卫（num>0 才扣，负库存不超发）；**盘盈/盘亏天然适配**：盘点为设值式无负数守卫（`checkAwardStock`），num 从 0 盘回正=补货、盘负=盘亏，实时驱动"剩余数量变化" |
| 4 | 等级/优先级=`activityrule` 扩展 **ruleType=5**（阶梯奖品行） | 现成列复用：`asid`（挂券奖品）、`sort`（优先级升序=降级顺序）、`status`（启停）；**新增列 `grade`**（tinyint 等级号 1/2/3，展示与约束用）；同优先级**随机**，不做同级禁配约束 |
| 5 | 签约发一张；发放即领取 | 签约结算时数量够 → `awardstock.num −1` + 券行 **state=2 已领**（"签约标记已领"）；发放即终态 |
| 6 | **签约时数量不够 → 不标已领、不作废** | 预占行保持 state=0 初始等待；**后续领取功能复用同一决策函数实时判断剩余数量变化**（补货/盘亏/退回），有货即发放已领（签约后领取闭环），仍无货拒绝领取 |
| 7 | 降级换行：预占行 state=1 失效（content 记降级）+ 新等级行 state=2 已领 | 对齐抽奖引擎"回收-补发"模式，不原地改 asid（保配置关联历史） |
| 8 | 退单**不自动回收**（一期） | 签约发放即终态；退单回收列为下游待讨论项 |
| 9 | **awardrecord 补记录** | 发放扣库存时同事务落 `AwardRecordPO.init(awardStockPO, operater, orderId, TYPE_XG_INT(出库), SUBTYPE_RECEIVE_INT(领取), ONETYPE_DECORATION_INT, isStock, unitPrice, num=1, content)`——对齐 receive 链；operater=签约人/领取人 |
| 10 | rule 维护入口：本期 SQL 配置 | activityrule 现状零端点零 UI；维护 UI 单独立项（下游待讨论项） |
| 11 | 🔴type=30 **不参与 makeDecorationPayment 抵扣行为**（2026-11-08 用户约束） | makeDecorationPayment 的款项金额=提交额−couponCut（couponCut=券族{0,10,20} isPayment=CAL 合计）——type=30 不在券族**天然不参与**；⚠️回归红线：任何人扩 TYPE_COUPON_FAMILY/改圈定逻辑必须保持 30 排除（30 是收款配比凭证，进抵扣会双重扣减）；落行 isPayment=1 双保险 |

## 四、核心流程与状态机

**决策函数 settle(orderId, 触发场景)**——参与/签约/领取三时点共用，实时按 `awardstock.num` 水位评估：

```
settle(orderId, scene):
  1. 活动定位：
       参与 → company + 窗口内 + type=30 定位新活动（照 queryActivityForLottery 模式）
       签约结算/领取 → 🔴以该单预占行的 aid 锚定活动（审查修正：参与在窗内、签约/领取可在窗外，
         按当前窗口重定位会查不到活动致预占永不结算——预占权益兑现不受窗口关闭影响）
  2. 读该活动启用规则行(ruleType=5, status=0)按 sort 升序（同 sort 随机）
  3. scene=参与 → 按水位选等级（num>0 的最高优先级，只读不扣库存）：
       找到 → 预占：decorationactivityitem 落行(type=30, asid, state=0, money=对应 activityitem 面值,
              no=LD+daiId, 不扣库存) + decorationactivity 关联行（幂等：已有关联行跳过）
       全无货 → 拒绝参与（新错误码，"活动奖品已清零"；无规则行同拒绝）
  4. scene=签约结算/领取 → 🔴原子扣减降级循环（审查修正：两单并发抢同一等级最后一张，
     "先查后扣"会双双命中致 num=−1 超发——改逐等级行原子扣减）：
       逐等级行（sort 升序）：UPDATE awardstock SET num=num-1 WHERE asId=? AND num>0
         affected=1 → 发放等级 L 确定；affected=0（被并发抢空）→ 尝试下一优先级
       全部等级行扣减失败 = 全清零：
         签约结算 → 预占行保持 state=0（等库存变化后领取），无缓存行
         领取 → 拒绝（库存不足）
  5. 发放落行（签约/领取，扣减成功后；幂等=该单已有 state=2 阶梯券行则跳过）：
       该单 state=0 预占行 且 asid==L.asid → 原行生效：state=2 已领 + awardrecord + record
       预占行缺失/已失效/降级（asid!=L.asid，含预占行被误作废的场景——结算容忍并按规则行重发）
         → 预占行(若有) state=1 失效(content 记降级)
         + 新等级行 state=2 已领（money=对应 activityitem 面值, no=LD+daiId）+ awardrecord + record
```

**触发点插桩（3 处）**：

| 时点 | 位置 | 动作 |
| --- | --- | --- |
| 参与 | `DecorationActivityServiceImpl.addDecorationActivity`（装修单页参加活动） | 参加的活动为 type=30 时调 settle(参与)：落关联行 + 预占券行 |
| 签约 | `DecorationContractServiceImpl`（contractTime 落定，:799 附近）+ `DecorationServiceImpl`（另一签约路径，:1358） | 对该单预占的 type=30 活动调 settle(签约结算，以预占行 aid 锚定——窗口外签约同样结算) |
| 领取 | `DecorationActivityItemServiceImpl.receiveDecorationActivityItem` 对 type=30/state=0 行加分支 | 走 settle(领取) 决策（不直接标已领），无货拒绝 |

## 七、测试要点（草案）

参与（有货预占/全清零拒绝/无规则行拒绝）→ 签约（原等级发放已领/降级换行/全清零保持初始/**窗口外签约照常结算**）→ 领取（补货后签约后领取/仍无货拒绝）→ 幂等（重签跳过）→ **并发原子扣减（两单抢最后一张：成功方发放、失败方自动降级，num 恒≥0）** → 金额口径（type=30 不进 couponCut/thingCut）→ awardrecord（出库/领取行成对）→ 盘点驱动（盘盈补货后领取成功、盘亏后拒绝）→ **预占行被误作废后签约仍可结算**。
