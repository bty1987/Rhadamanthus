# 增减单"暂扣"状态功能方案

> 模块: quotation（addreduce 增减单）
> 状态: **方案定稿待开发**（2026-09-04 与需求方确认口径，未实施）
> 生产数据: quotation.addreduce 45.7 万行（type=0 增项 28.2 万，其中未付款约 2.2 万）

---

## 一、需求背景

增项增减单（type=0）需要一种"暂扣"冻结机制：客户尚未交钱的增减单，标记暂扣后锁定内容修改，但不阻断付款流程——交钱后状态照常流转已付款/已确认。

### 需求口径（两轮确认后的最终版）

| 操作 | 暂扣（status=4）期间 |
|---|---|
| 明细（addreduceitem）工程量修改 | ❌ 禁止 |
| 明细添加 / 删除 | ❌ 禁止 |
| 明细折扣（item.discount，updateAddReduceItemForAdvance） | ❌ 禁止 |
| 整单删除（deleteAddReduce） | ❌ 禁止 |
| 管理费折扣（manageDiscount/Rate/Price） | ❌ 禁止 |
| 税金折扣（taxDiscount/Rate/Price） | ❌ 禁止 |
| 整单折扣 addreduce.discount | ✅ 允许（折扣弹窗照用） |
| 工费标识驳回（rejectAddReduceForSalary） | ❌ 禁止 |
| 工费标识标记（openAddReduceForSalary） | ✅ 允许 |
| 明细排序（updateAddReduceItemForIndex） | ✅ 允许 |
| 决算流程（统计/决算折扣调整 updateAddReduceForAccount） | ✅ 不受影响，决算统计排除暂扣单 |
| 提交 / 收款 / 确认等状态流转 | ✅ 照常（暂扣后可直接走付款，交钱后正常变已付/确认） |

### 关键设计决策（需求方拍板）

1. **复用 status 字段，取值 4，不新增列**——生产表 45.7 万行能不加字段就不加。
2. **决算流程排除暂扣状态**——经审计为天然排除（白名单式判断），零改动（见第四节）。
3. **明细折扣不可改、明细排序可操作、整单不可删除；app 版前端优先级最低（暂不做）**。
4. 附带默认口径（实施时如需调整再确认）：标记暂扣限 `paytype==0`（需付款的增项；下拨/特批类无交钱语义）。

## 二、现状梳理（实施前必读）

### 状态机（现状 0-3，本方案新增 4）

| 值 | 常量 | 含义 | 进入方式 |
|---|---|---|---|
| 0 | STATUS_UNSUBMIT_INT | 初始（未提交） | 新建 / cancel 撤销回退 |
| 1 | STATUS_SUBMIT_INT | 已提交 | submit（批量，创建应收款项 decorationpayment 并挂 dpId） |
| 2 | STATUS_PAYED_INT | 已付款 | 收款确认（payment 模块按 dpId 批量置位，**无前置状态校验**） |
| 3 | STATUS_CONFIRMED_INT | 已确认 | confirm（仅 {2,3} 可确认） |
| **4** | **STATUS_HOLD_INT（新增）** | **暂扣** | openAddReduceForHold（0/1 → 4） |

相关既有标识：`isSalary`（工费标识 0/1，锁明细删改额抛 200064/200065，与本方案拦截模式同构，是其实现先例）、`isAffirm`（客户确认，不涉及）。

### 流转联动要点（决定 4 的流转规则的事实依据）

- `submitAddReduce` 是**批量**接口：多单一起提交 → 汇总金额创建**一笔** decorationpayment（应收，未收状态）→ 各单 `setStatus(1)+setDpId(款项id)`；校验 `status==0 && dpId==0`。
- 收款确认（payment 模块）按 dpId 查出关联增减单**批量直接 setStatus(2)**，不校验原状态 → 任何状态（含 4）挂了款项即可被置已付。
- `cancelAddReduce` 按 dpId 批量 1→0 并删除款项（校验款项未收 + status==1）。
- `unpayAddReduce` 是 status=0 时把增减单转 paytype（下拨/特批/不退），非"退回未付"。
- 前端常量 `constant.quotation().addreduce.STATUS_*` 由 `communion.constant` 表驱动（clazz=addreduce，key=0-3 四行），加枚举只需插表，constant.js 不动。

## 三、暂扣流转模型（终稿）

```
                 标记暂扣 openAddReduceForHold (仅 type=0, paytype=0, status∈{0,1})
  0 初始 ──────────────────────────────┐
  │ submit(批量,建应收,挂dpId)           ▼
  ▼                                 4 暂扣 ──解除 rejectAddReduceForHold──> dpId==0 ? 回0 : 回1
  1 提交 ─────────标记暂扣──────────────┤
                                      ├─ submit 放宽(4→1, 仅dpId==0的单; 建应收后正常走收款)
                                      └─ 收款确认 4→2 (dpId!=0的单, payment无状态校验天然放行)
  2 已付款 ──confirm──> 3 已确认
```

- 标记：0/1 → 4（两种来源都允许）；
- 解除：4 → **按 dpId 推断回退目标**（dpId==0 → 回 0；dpId!=0 → 回 1），无需额外记录来源；
- 走出暂扣的三条路：手动解除 / 提交（4→1）/ 收款（4→2）；交钱后状态照常 2→3，暂扣语义随流转自然终结。

### 5.2 新增接口一对（对齐工费 open/rejectAddReduceForSalary 先例，三层同名，方法排序按 update 段后归置）

**`openAddReduceForHold`**（标记暂扣）：

```java
AddReducePO addReducePO = addReduceDao.get(addReduceVO.getArId());
if (addReducePO == null) throw new FLException(200060, "增减单不存在");
if (addReducePO.getType() != AddReducePO.TYPE_ADD_INT) throw new FLException(200069, "仅增项增减单可暂扣");
if (addReducePO.getPaytype() != AddReducePO.PAYTYPE_PAY_INT) throw new FLException(200061, "增减单状态不可操作");
if (!Arrays.asList(AddReducePO.STATUS_UNSUBMIT_INT, AddReducePO.STATUS_SUBMIT_INT).contains(addReducePO.getStatus()))
    throw new FLException(200061, "增减单状态不可操作");
addReducePO.setStatus(AddReducePO.STATUS_HOLD_INT);
addReduceDao.update(addReducePO);
LogUtils.log(userId, "增减单标记暂扣", "增减单", arId);
```

**`rejectAddReduceForHold`**（解除暂扣）：

```java
if (addReducePO == null) throw new FLException(200060, "增减单不存在");
if (addReducePO.getStatus() != AddReducePO.STATUS_HOLD_INT) throw new FLException(200068, "增减单未暂扣,不可解除");
addReducePO.setStatus(addReducePO.getDpId() == 0 ? AddReducePO.STATUS_UNSUBMIT_INT : AddReducePO.STATUS_SUBMIT_INT);
addReduceDao.update(addReducePO);
LogUtils.log(userId, "增减单解除暂扣", "增减单", arId);
```

## 九、实施顺序与自测清单

1. 后端（PO 常量 → error.md → 2 新接口 → 5 处修改）→ 打 jar；
2. 前端（api → addReduceIndex → addReducePart）；
3. SQL（constant 行先行，权限后配）；
4. 自测项：
   - type=0 未付款单标记暂扣 → 列表状态"暂扣"；
   - 暂扣中：改工程量/增删明细/明细折扣/管理费税金折扣/工费驳回/整单删除 → 均报错；改 discount → 成功且联动金额更新；
   - 暂扣中：排序可操作、决算折扣调整可操作、工费标记可操作；
   - 决算统计页金额不含暂扣单；
   - dpId==0 的暂扣单：提交 → 状态变"提交" → 收款 → "已付款"；dpId!=0 的暂扣单：直接收款 → "已付款" → 确认 → "已确认"；
   - 解除暂扣：dpId==0 回"初始"、dpId!=0 回"提交"；
   - type=1/2（减项/漏项）标记暂扣 → 报 200069；
   - isSalary 已标记的单标记暂扣 / 暂扣单标记工费 → 两种锁叠加互不干扰。
