# 萤石摄像头接入完整方案

> 文档定位：当前 ERP/施工/客户侧系统接入第三方摄像头产品的方案设计。
>
> 目标效果：客户可以通过客户侧 H5/小程序查看工地图片、可播放图片集、直播内容，并在高价值场景下查看回放或生成视频。
>
> 编写日期：2026-08-18

---

## 一、核心结论

摄像头接入不应被设计成一个简单的“图片上传功能”，而应作为一个独立的“工地视频资源服务”。

推荐第一阶段落地：

1. 按装修单/施工单绑定萤石摄像头。
2. 客户侧通过 H5/小程序查看直播。
3. 支持客户、内部人员、施工节点事件主动抓图。
4. 定时抓图形成“今日工地图片集”。
5. 前台通过轮播/幻灯片方式播放图片集，形成类似视频的“工地快看”。
6. 真正生成 MP4 视频只用于竣工交付、外部分享、案例宣传、争议证据等重场景。

一句话原则：

> 后台负责设备绑定、抓图、存储、授权和素材组织；前台负责图片集播放体验；视频生成作为按需增强能力。

## 二、业务目标

### 2.1 客户侧目标

客户希望快速知道：

- 我家现在有没有施工。
- 现场现在是什么样。
- 今天是否有变化。
- 当前施工节点是否推进。
- 关键节点是否有过程记录。
- 出现问题时是否能留证反馈。

因此客户侧不一定每次都需要看直播。很多时候，“今日快看”“节点影集”“图片集播放”比直播更轻、更稳定、更容易消费。

### 2.2 内部管理目标

内部希望实现：

- 工地透明化管理。
- 监理/项目经理远程巡检。
- 施工节点图片留档。
- 客户反馈和投诉证据补充。
- 摄像头在线状态巡检。
- 后续形成施工日报、工地日历、竣工回顾视频。

### 2.3 产品边界

本方案不建议第一阶段直接做完整视频生产平台。第一阶段应先跑通：

```text
摄像头绑定 -> 授权观看 -> 抓图入库 -> 图片集展示 -> 前台播放
```

视频生成能力在后续作为“重场景能力”补充。

## 三、当前系统可复用落点

当前 Rhadamanthus 系统中已有一些天然挂接点：

| 系统能力 | 可复用点 | 说明 |
|---|---|---|
| 装修单 | `orderId` | 客户和业务的主关联对象 |
| 施工单 | `cid` | 摄像头更适合挂在施工单/施工现场 |
| 施工节点 | `csid` / `cnid` / `schedule` | 抓图可归档到具体施工阶段 |
| 施工图片 | `constructiondrawing` | 可承接抓图后的长期图片资料 |
| 客户通知 | `customernotice` | 可向客户展示节点完成、图片/影集/视频入口 |
| OSS | 临时 URL、图片处理 | 可用于抓图转存、封面图、客户访问临时授权 |
| 微信/小程序/H5 | 客户入口 | 客户实际观看应落到 H5 或小程序，而不是 ERP 后台 |
| SystemConfig | 第三方配置 | 可存储萤石 appKey/appSecret/host 等配置 |

### 3.1 不建议直接塞进现有图片表

现有施工图片表适合保存“已经产生的图片素材”，不适合直接表达摄像头设备、播放地址、在线状态、客户可见权限、抓图策略等动态能力。

因此建议新增摄像头模块，再把抓图结果按需沉淀到施工图片、客户通知等现有体系中。

## 四、萤石接入链路

萤石云开放平台通常采用如下链路：

```text
appKey/appSecret
        ↓
获取 accessToken
        ↓
设备/通道管理 deviceSerial + channelNo
        ↓
获取直播地址 / 抓图 / 录像回放
        ↓
返回临时播放地址或图片地址给业务系统
        ↓
客户侧 H5/小程序展示
```

> 具体接口名称、字段、播放协议以萤石开放平台最新文档为准。本方案按“萤石开放平台常见 LAPP 接口模式”设计，代码落地前需再次核对官方文档与账号权限。

### 4.1 后端必须代理厂商接口

客户前端不应直接调用萤石开放平台接口。

原因：

1. `appSecret` 不能暴露。
2. `accessToken` 不能暴露。
3. 设备序列号、验证码属于敏感信息。
4. 必须先校验客户是否有权查看该装修单。
5. 播放地址应短时有效，避免长期外泄。
6. 需要记录客户观看、抓图、分享等访问日志。

### 4.2 推荐调用方式

```text
客户前端
  -> Rhadamanthus 后端接口
    -> 校验登录/客户身份/订单关系/可见时间段
    -> 获取或刷新萤石 accessToken
    -> 调用萤石直播/抓图/录像接口
    -> 返回临时 URL 或图片集数据
```

## 六、数据模型设计

### 6.1 摄像头设备表

表名建议：`construction.camera`

```sql
CREATE TABLE construction.camera (
    cid BIGINT NOT NULL AUTO_INCREMENT,
    orderId VARCHAR(32) NOT NULL COMMENT '装修单号',
    constructionId BIGINT DEFAULT 0 COMMENT '施工单ID, 对应 construction.cid',
    provider VARCHAR(32) NOT NULL DEFAULT 'ys7' COMMENT '厂商: ys7/hikvision/dahua',
    deviceSerial VARCHAR(128) NOT NULL COMMENT '设备序列号',
    channelNo INT NOT NULL DEFAULT 1 COMMENT '通道号',
    name VARCHAR(64) DEFAULT NULL COMMENT '摄像头名称',
    verifyCode VARCHAR(256) DEFAULT NULL COMMENT '设备验证码, 建议加密存储',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 0停用, 1启用',
    onlineStatus TINYINT NOT NULL DEFAULT 0 COMMENT '在线状态: 0未知/离线, 1在线',
    openLive TINYINT NOT NULL DEFAULT 1 COMMENT '客户是否可看直播',
    openCapture TINYINT NOT NULL DEFAULT 1 COMMENT '客户是否可抓图/刷新图片',
    openPlayback TINYINT NOT NULL DEFAULT 0 COMMENT '客户是否可看回放',
    openAlbum TINYINT NOT NULL DEFAULT 1 COMMENT '客户是否可看图片集/影集',
    visibleStart VARCHAR(8) DEFAULT '08:00' COMMENT '每日可见开始时间',
    visibleEnd VARCHAR(8) DEFAULT '18:00' COMMENT '每日可见结束时间',
    company INT NOT NULL DEFAULT 0 COMMENT '公司',
    createTime DATETIME NOT NULL,
    updateTime DATETIME DEFAULT NULL,
    PRIMARY KEY (cid),
    KEY idx_camera_orderId (orderId),
    KEY idx_camera_constructionId (constructionId),
    KEY idx_camera_provider_device (provider, deviceSerial, channelNo)
) COMMENT='施工摄像头设备表';
```

说明：

- `orderId` 是客户侧授权的核心字段。
- `constructionId` 用于施工模块内部关联。
- `provider` 先固定为 `ys7`，后续预留多厂商。
- `verifyCode` 必须加密存储，不建议明文。
- 客户可见能力拆成 `openLive/openCapture/openPlayback/openAlbum`，便于分阶段开放。

### 6.2 摄像头媒体表

表名建议：`construction.cameramedia`

```sql
CREATE TABLE construction.cameramedia (
    cmid BIGINT NOT NULL AUTO_INCREMENT,
    orderId VARCHAR(32) NOT NULL COMMENT '装修单号',
    constructionId BIGINT DEFAULT 0 COMMENT '施工单ID',
    cameraId BIGINT NOT NULL COMMENT '摄像头ID',
    csid BIGINT DEFAULT 0 COMMENT '施工节点ID',
    cnid BIGINT DEFAULT 0 COMMENT '施工节点类型ID',
    mediaType TINYINT NOT NULL DEFAULT 1 COMMENT '媒体类型: 1图片, 2视频',
    source TINYINT NOT NULL DEFAULT 0 COMMENT '来源: 0系统, 1客户, 2内部人员, 3定时, 4节点, 5告警',
    originUrl VARCHAR(512) DEFAULT NULL COMMENT '厂商原始URL',
    mediaUrl VARCHAR(512) NOT NULL COMMENT '系统可访问URL, 推荐OSS地址',
    coverUrl VARCHAR(512) DEFAULT NULL COMMENT '封面图',
    captureTime DATETIME NOT NULL COMMENT '抓图/采集时间',
    visible TINYINT NOT NULL DEFAULT 1 COMMENT '客户是否可见',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 0无效, 1有效',
    company INT NOT NULL DEFAULT 0,
    createTime DATETIME NOT NULL,
    PRIMARY KEY (cmid),
    KEY idx_cameramedia_order_time (orderId, captureTime),
    KEY idx_cameramedia_camera_time (cameraId, captureTime),
    KEY idx_cameramedia_node (csid, cnid)
) COMMENT='摄像头图片/视频素材表';
```

说明：

- 第一阶段 `mediaType` 主要使用图片。
- `originUrl` 可记录萤石返回地址，但客户展示建议用 `mediaUrl`。
- `mediaUrl` 推荐转存 OSS 后保存，避免厂商图片 URL 过期。
- `visible` 用于后台隐藏不适合客户查看的图片。

### 6.3 摄像头访问日志表

表名建议：`construction.cameraaccess`

```sql
CREATE TABLE construction.cameraaccess (
    caid BIGINT NOT NULL AUTO_INCREMENT,
    orderId VARCHAR(32) NOT NULL,
    cameraId BIGINT DEFAULT 0,
    viewerType TINYINT NOT NULL COMMENT '访问人类型: 1客户, 2内部员工, 3分享访客',
    viewerId VARCHAR(64) DEFAULT NULL COMMENT '客户/员工/openId/unionId/分享标识',
    action VARCHAR(32) NOT NULL COMMENT 'live/capture/album/playback/video/share',
    result TINYINT NOT NULL DEFAULT 1 COMMENT '结果: 0失败, 1成功',
    message VARCHAR(256) DEFAULT NULL COMMENT '失败原因或备注',
    ip VARCHAR(64) DEFAULT NULL,
    userAgent VARCHAR(256) DEFAULT NULL,
    createTime DATETIME NOT NULL,
    PRIMARY KEY (caid),
    KEY idx_cameraaccess_order_time (orderId, createTime),
    KEY idx_cameraaccess_viewer (viewerType, viewerId)
) COMMENT='摄像头访问日志表';
```

```sql
    visible TINYINT NOT NULL DEFAULT 1,

    createTime DATETIME NOT NULL,

    PRIMARY KEY (caid),
```

## 七、后端接口设计

### 7.1 后台设备管理接口

```text
pageConstructionCamera.do
queryConstructionCameraByOrderId.do
addConstructionCamera.do
updateConstructionCamera.do
deleteConstructionCamera.do
updateConstructionCameraForStatus.do
updateConstructionCameraForVisible.do
```

用途：

- 后台按装修单绑定摄像头。
- 配置客户是否可看直播、影集、回放。
- 配置可见时间段。
- 查看设备在线状态。

### 7.2 客户侧直播接口

```text
queryConstructionCameraLiveUrl.do
```

入参：

```text
orderId
cameraId
```

后端处理：

1. 校验客户登录或访问 token。
2. 校验客户与 `orderId` 的关系。
3. 查询摄像头是否启用。
4. 校验 `openLive` 和可见时间段。
5. 获取萤石 `accessToken`。
6. 调用萤石直播地址接口。
7. 返回临时播放地址。
8. 写入访问日志。

返回示例：

```json
{
  "camera": {
    "cameraId": 12,
    "name": "客厅施工位",
    "status": 1,
    "onlineStatus": 1
  },
  "play": {
    "url": "https://xxx/live.m3u8",
    "protocol": "hls",
    "expireTime": "2026-08-18 18:30:00"
  }
}
```

### 7.3 抓图接口

```text
captureConstructionCamera.do
```

入参：

```text
orderId
cameraId
triggerType
triggerId
csid
```

`triggerType` 建议：

| triggerType | 说明 |
|---|---|
| customer | 客户主动刷新/反馈截图 |
| user | 内部人员主动抓图 |
| schedule | 定时任务抓图 |
| node | 施工节点事件触发 |
| alarm | 设备告警触发 |
| system | 系统巡检触发 |

后端处理：

1. 校验权限。
2. 对客户触发做限流。
3. 调用萤石抓图接口。
4. 必要时下载图片并转存 OSS。
5. 写入 `cameramedia`。
6. 如属于节点抓图，可同步写入 `constructiondrawing`。
7. 返回图片地址。

返回示例：

```json
{
  "media": {
    "mediaId": 801,
    "mediaType": 1,
    "url": "https://oss.xxx/camera/xxx.jpg",
    "captureTime": "2026-08-18 10:00:00"
  }
}
```

### 7.4 图片集接口

```text
queryConstructionCameraMedia.do
```

支持条件：

```text
orderId
```

## 八、抓图策略设计

抓图不要只设计一种触发方式，建议统一成“三类主动触发 + 定时触发 + 事件触发”。

### 8.1 客户主动触发

场景：

- 客户点击“刷新现场图片”。
- 客户点击“保存当前画面”。
- 客户提交问题反馈时自动抓一张。

限制：

```text
同一客户 + 同一摄像头 30-60 秒内只能抓一次
同一订单每天最多抓 N 次
夜间或非开放时间禁止抓图
竣工/停工/退单后禁止客户抓图
```

### 8.2 内部人员主动触发

场景：

- 监理远程巡检。
- 项目经理查看现场。
- 质检抽查。
- 客诉取证。

内部抓图可不受客户限流影响，但仍要记录日志。

### 8.3 施工节点事件触发

场景：

```text
节点开工 -> 抓图
节点完工 -> 抓图
节点验收 -> 抓图
返工开始 -> 抓图
返工完成 -> 抓图
```

建议：节点事件抓图属于高价值资料，推荐长期保存，并挂到施工图片或施工日志。

### 8.4 设备事件触发

如果萤石支持事件回调，可接入：

```text
设备离线
设备上线
移动侦测
遮挡告警
异常声音
夜间异常移动
```

处理建议：

- 离线/上线：记录事件，通知内部人员，不一定给客户展示。
- 移动/遮挡：可抓图，但默认内部可见。
- 涉及隐私或误报的告警，不建议自动推给客户。

### 8.5 定时抓图

定时抓图适合形成“施工日报”和“工地日历”。

推荐第一版频率：

```text
09:00
11:30
14:00
17:00
```

或：

```text
施工时间内每 2 小时抓一次
```

不建议每几分钟抓一次，原因：

- 接口频率压力大。
- 图片数量膨胀。
- 存储成本上升。
- 客户实际消费不了。
- 现场隐私风险增加。

定时任务过滤条件：

```text
只抓施工中订单
只抓启用摄像头
只抓在线设备
只在客户/公司设置的施工时间内抓
只抓 openAlbum 或 openCapture 开启的设备
```

## 九、图片集与前台播放方案

### 9.1 核心原则

不一定要真正制作视频。很多日常场景使用“图片集 + 前台自动播放”即可达到客户感知效果。

推荐产品规则：

```text
图片太少时展示图片集；
图片适中时展示可播放影集；
图片太多时按时间均匀抽帧生成播放序列；
只有分享、归档、宣传等重场景才生成真实视频。
```

### 9.2 前台播放形态

客户侧页面可以展示：

```text
我的工地
- 实时直播
- 今日快看
- 节点影集
- 全部图片
- 历史回放
```

“今日快看”本质是图片自动播放：

```text
自动播放 8-12 张图片
每张停留 1.5-2 秒
显示拍摄时间
显示施工节点
支持暂停/继续
支持上一张/下一张
支持查看大图
```

### 9.3 播放规则

建议规则：

| 图片数量 | 展示方式 |
|---|---|
| 0 张 | 展示空状态：今日暂无现场图片 |
| 1-2 张 | 不自动播放，只展示图片 |
| 3-12 张 | 全量自动播放，每张约 2 秒 |
| 13-30 张 | 全量或精选播放，每张约 1.5 秒 |
| 30 张以上 | 后端精选 12-20 张作为播放序列，其余放入图片集 |

### 9.4 图片太多时的均匀抽帧

如果当天有 80 张图片，不建议一次全部给前端自动播放。后端可以按时间均匀抽取 12 张：

```text
09:00
09:45
10:30
11:15
12:00
13:30
14:15
15:00
15:45
16:30
17:15
18:00
```

前台展示两个入口：

```text
播放快看：精选 12 张
查看全部：完整图片集
```

### 9.5 前台技术实现

H5：

- Swiper/轮播组件。
- 图片预加载。
- CSS 淡入淡出。
- 自定义进度条。
- 大图预览。

小程序：

- `swiper` + `image`。
- `setInterval` 控制播放。
- 使用 `previewImage` 查看大图。
- 图片域名加入小程序合法域名。

### 9.6 前台播放优于视频生成的原因

| 维度 | 图片集播放 | 生成 MP4 |
|---|---|---|
| 实现成本 | 低 | 高 |
| 生成等待 | 无 | 有 |
| 内容更新 | 实时 | 需重新生成 |
| 失败影响 | 单张失败不影响整体 | 任务失败整个视频不可用 |
| 存储成本 | 低 | 高 |
| 分享保存 | 一般 | 好 |
| 证据固化 | 一般 | 好 |
| 日常查看 | 推荐 | 不推荐默认使用 |

## 十、真实视频生成方案

### 10.1 什么时候需要生成 MP4

真实视频只建议用于高价值场景：

1. 竣工交付：生成从开工到竣工的全周期视频。
2. 节点交付：水电、瓦工、木工、油工等阶段完成后生成节点视频。
3. 外部分享：客户要转发给家人或保存到手机。
4. 企业宣传：优质工地案例沉淀成宣传素材。
5. 争议证据：某个时间段需要固化证据。
6. 展厅/大屏：连续播放时 MP4 更稳定。

### 10.2 视频生成链路

```text
摄像头抓图
  -> 图片转存 OSS
  -> 按订单/节点/日期/摄像头分组
  -> 生成视频任务
  -> 后台 FFmpeg 合成 MP4
  -> 上传 OSS
  -> 客户通知或页面展示
```

### 10.3 视频模板

| 模板 | 图片数量 | 视频时长 | 场景 |
|---|---:|---:|---|
| 日报视频 | 4-8 张 | 8-15 秒 | 每日工地回顾 |
| 节点视频 | 10-30 张 | 15-45 秒 | 节点完工交付 |
| 全周期视频 | 每节点 5-10 张 | 60-120 秒 | 竣工交付 |
| 异常视频 | 事件前后若干张 | 10-20 秒 | 争议/告警留证 |

### 10.4 视频任务表

```sql
CREATE TABLE construction.cameravideo (
    cvid BIGINT NOT NULL AUTO_INCREMENT,
    orderId VARCHAR(32) NOT NULL,
    cameraId BIGINT DEFAULT 0,
    type TINYINT NOT NULL COMMENT '视频类型: 1日报, 2节点, 3全周期, 4异常',
    title VARCHAR(128) NOT NULL,
    coverUrl VARCHAR(512) DEFAULT NULL,
    videoUrl VARCHAR(512) DEFAULT NULL,
    duration INT DEFAULT 0,
    imageCount INT DEFAULT 0,
    status TINYINT NOT NULL DEFAULT 0 COMMENT '0待生成, 1生成中, 2成功, 3失败',
    message VARCHAR(256) DEFAULT NULL,
    company INT NOT NULL DEFAULT 0,
    createTime DATETIME NOT NULL,
    updateTime DATETIME DEFAULT NULL,
    PRIMARY KEY (cvid),
    KEY idx_cameravideo_order (orderId, type)
) COMMENT='摄像头视频成品表';
```

视频生成必须异步执行，不建议客户请求同步等待。

## 十三、权限与隐私控制

### 13.1 客户权限

客户查看必须满足：

```text
客户已登录或分享 token 有效
客户与 orderId 存在合法关系
摄像头启用
对应能力开关开启
当前时间在可见时间段内
订单状态允许查看
```

订单状态建议：

| 订单状态 | 客户直播 | 图片集 | 历史影集 |
|---|---|---|---|
| 施工中 | 可开通 | 可开通 | 可开通 |
| 暂停施工 | 可关闭 | 可查看历史 | 可查看历史 |
| 竣工 | 默认关闭 | 可查看历史 | 可查看历史 |
| 退单/终止 | 关闭 | 关闭或仅内部 | 关闭或仅内部 |

### 13.2 敏感数据

敏感数据包括：

- 萤石 `appSecret`。
- 萤石 `accessToken`。
- 设备序列号。
- 设备验证码。
- 长期播放地址。
- 客户身份 token。

要求：

1. `appSecret` 只存后端配置。
2. 设备验证码加密存储。
3. 客户侧不返回 `accessToken`。
4. 播放地址短时有效。
5. 分享链接设置有效期和访问次数。
6. 所有直播、抓图、影集访问写日志。

### 13.3 隐私策略

施工现场可能拍到人员、客户物品、生活痕迹。建议：

- 默认只允许订单客户查看。
- 对外分享必须客户主动触发。
- 夜间默认关闭直播和抓图。
- 告警图片默认内部可见。
- 后台可隐藏不适合客户查看的图片。
- 竣工后关闭实时直播，只保留历史资料。

## 十七、分阶段实施计划

### 阶段 1：基础闭环

目标：客户能看直播，系统能抓图，后台能管理设备。

范围：

- 摄像头设备表。
- 摄像头媒体表。
- 萤石 `accessToken` 管理。
- 后台绑定摄像头。
- 客户获取直播地址。
- 客户/内部人员主动抓图。
- 图片转存 OSS。
- 访问日志。

不做：

- 回放。
- 视频生成。
- 告警回调。
- 多厂商。

### 阶段 2：定时抓图与图片集播放

目标：形成“今日工地快看”。

范围：

- 定时抓图任务。
- 图片集查询。
- 播放序列接口。
- 前台图片集自动播放。
- 图片太多时均匀抽取。
- 后台图片可见性管理。

### 阶段 3：施工节点影集

目标：将图片和施工节点结合。

范围：

- 节点开工/完工/验收触发抓图。
- 节点影集。
- 节点图片归档到施工图片。
- 客户通知跳转节点影集。

### 阶段 4：回放与事件告警

目标：增强远程巡检和异常管理。

范围：

- 录像回放。
- 最近 24 小时/7 天回放。
- 萤石事件回调。
- 离线/上线提醒。
- 告警图片内部可见。

### 阶段 5：视频生成

目标：重场景视频化。

范围：

- 竣工全周期视频。
- 节点交付视频。
- 投诉证据视频。
- FFmpeg 异步任务。
- 视频上传 OSS。
- 分享链接。

## 十八、验收标准

### 18.1 第一阶段验收

- 后台可以绑定摄像头到装修单。
- 后台可以启用/停用客户直播。
- 客户只能看到自己订单的摄像头。
- 客户可以获取直播地址并播放。
- 客户可以主动抓图，且受限流控制。
- 内部人员可以主动抓图归档。
- 抓图结果转存 OSS 并入库。
- 访问日志完整记录。
- 非可见时间段不能查看直播。
- 竣工/停工/退单等状态能按规则关闭权限。

### 18.2 第二阶段验收

- 定时任务按设定时间抓图。
- 客户侧能看到今日图片。
- 客户侧能播放今日快看。
- 图片数量过少时不自动播放。
- 图片数量过多时后端返回精选播放序列。
- 后台能隐藏不适合客户查看的图片。

### 18.3 第三阶段验收

- 节点事件能触发抓图。
- 节点影集能按施工阶段查看。
- 节点完成后能生成客户通知。
- 节点图片能与施工图片体系联动。

## 十九、主要风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 播放协议兼容 | H5/小程序对 HLS/FLV/RTMP 支持不同 | 落地前用真实设备和真实账号测试 |
| 萤石接口权限 | 抓图/回放/事件可能需要额外权限或套餐 | 开发前确认开放平台账号能力 |
| 图片 URL 过期 | 厂商返回图片可能短期有效 | 关键图片转存 OSS |
| 访问量和频率 | 客户频繁抓图可能触发限流 | 做客户限流和每日上限 |
| 隐私争议 | 施工现场可能拍到敏感内容 | 时间段、可见开关、后台隐藏、访问日志 |
| 存储膨胀 | 定时抓图会快速增加图片 | 分类保留和定期清理 |
| 视频生成过重 | FFmpeg 任务需要算力和排队 | 第一阶段用图片集播放替代视频 |
| 设备离线 | 客户打开后无法观看 | 在线巡检、离线提示、内部提醒 |

## 二十、最终推荐方案

推荐最终产品形态：

```text
客户侧：透明工地
- 实时直播
- 今日快看
- 节点影集
- 全部图片
- 历史回放
- 问题反馈
```

```text
后台侧：摄像头管理
- 绑定设备
- 查看直播
- 抓图归档
- 图片审核
- 客户可见控制
- 在线状态巡检
- 访问日志
```

落地路线：

```text
先直播 + 抓图
再图片集 + 前台播放
再节点影集
再回放/告警
最后按需生成视频
```

产品判断：

> 日常客户感知不需要默认生成视频。图片集加前台播放已经足够轻、快、可控；真正的视频生成留给竣工、分享、宣传、证据归档等高价值场景。

这样既能快速形成“客户能看到现场”的效果，又不会在第一阶段引入视频生成服务、队列、FFmpeg、存储膨胀和兼容性复杂度。
