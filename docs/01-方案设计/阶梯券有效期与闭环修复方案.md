# 阶梯券(type=30)有效期与闭环修复方案

> 2026-11-24 设计稿。基于《阶梯抽奖活动方案.md》《销售收款券配比方案.md》的增量调整。
> 范围: ① activityitem 物品级有效期 ② 预占/生效/使用三阶段判定补全 ③ 上版方案"第7节风险缺陷"的修复设计。
> **五项待拍板项已于 2026-11-24 全部拍板**(见 §7 拍板记录; 同日口径修正: 拍板1/3 收敛至 salespayment 层, decoration 层的退暂不处理), 本文档为定案稿, 可直接落码。

## 1. 名词与口径

| 名词 | 含义 |
|---|---|
| 预占(join) | 装修单参与活动, 插 `decorationactivityitem` 预占行(state=0), **不扣库存** |
| 生效(settle) | 签约结算(LADDER_SCENE_CONTRACT)或领取结算(LADDER_SCENE_RECEIVE), **原子扣库存**, 预占行 0→2 已领 |
| 使用 | 收款抵扣 `collectSalesPayment(daiIds)`, 券行 2→7 消耗, 落 `decorationscaledetail` |
| 有效窗口 | 见下, 逐边界独立解析 |

**窗口解析规则(需求1核心口径)**:

```
effectiveStart = activityitem.startTime ?? activity.startTime   // ?? = 逐边界兜底, 非整组覆盖
effectiveEnd   = activityitem.endTime   ?? activity.endTime
null           = 该边界不设限
```

- 物品行配了窗口 → 物品窗口**优先**; 没配的边界 → 回退活动窗口; 活动也没配 → 不设限(维持现状)。
- 边界判定含等号: `now < start` 或 `now > end` 才算窗外(与现有 140116 判定一致)。
- 窗口粒度 = activityitem 行(即档位)。同活动不同档可配不同窗口; 同 asid 多行不同窗按行独立判定(降级循环逐行过滤, 天然支持)。

**存量兼容**: 存量 activityitem 行两列均为 NULL → 回退活动窗口, 行为零变化, 零 backfill。

## 2. 三阶段判定矩阵(需求2核心口径)

| 阶段 | 数量判定 | 时间判定 | 现状 | 调整 |
|---|---|---|---|---|
| 选品 | — | ❌ | 下拉全量展示 | **type=30 窗外行隐藏**(拍板2) |
| 预占 | 水位找档(有货档最高面值, 全空 140117) | 140116 活动窗 | ✅数量 ✅活动窗 | 候选档按**物品窗**过滤 |
| 生效(签约) | 原子扣减降级循环(`num-1000 WHERE num>=1000`) | ❌无 | ✅数量 ❌时间 | 循环按**物品窗**过滤; 全窗已结束→预占行失效 |
| 生效(领取) | 同上 | ❌无 | 同上 | 同上, 全窗已结束→140121 拒绝 |
| 使用 | 一券一用/每单一张/money>0 | ❌无 | ✅ ❌ | 生效时回写 `expireTime`; 收款 140122 拦截 + 选券列表过滤 |

### 2.0 选品过滤(拍板2: 隐藏)

`queryActivityItemByAid`(information, operation 891) 为**共用接口**(申领页 decoration4activity ×3 / 详情面板 decoration4detail / 添加下拉 decorationUtils / sales4activity / materialActivity / **维护页 activityItem.js**)。处理方式:

- `ActivityVO` 加请求参数字段 `filterWindow`(接口入参绑定在 activity VO, 默认不过滤, 维护页零改动);
- `queryActivityItemByAid` 服务端: `filterWindow=1` 时, **仅对 type=30 行**按 §1 窗口解析判定, 窗外行剔除; 其余类型不涉窗, 原样返回;
- 业务侧选品入口传 `filterWindow=1`(共6处): decoration4activity ×3 / decoration4detail / sales4activity / materialActivity; **decorationUtils.initLadderPanel(阶梯奖品面板)不传**——面板是状态视图, 过期档上已持有的券(已领/已抵扣)必须可见;
- 引擎侧 140116/140117 守卫保留(fail-closed 双保险, 防绕过前端直调)。

### 2.1 预占(改动小)

`settleLadderActivityItem` 构建候选档 `priorityRules`(面值降序分档)时, 逐行按 §1 窗口解析过滤窗外行:

- JOIN: 活动窗 140116 检查保留(活动整体已关则参与先被拦); 物品窗过滤后空集 → 140117(文案不变)。
- 档位被窗外过滤 = 该档不可预占, 水位自动落到窗内有货的最高档。

### 2.2 生效(改动核心)

签约/领取共用原子扣减循环, 循环前按 §1 窗口过滤候选档:

- **窗内档可发**: 同档直转已领 / 异档失效换行, 逻辑不变。
- **降级越窗**: 预占档窗口已关但窗内有低档有货 → 降级到窗内档(轨迹注明)。
- **全部档不可发**时(窗内无货 或 窗内空集), 新增窗口结束判定:
  - 该活动全部 type=30 行均已过 `effectiveEnd` → **窗口已关闭, 不再等**:
    - 签约场景: 预占行 0→1 失效, content 追加"(有效期外失效)", 记轨迹, **不阻断签约**(与既有"数量不够保持初始不阻断签约"同构, 幂等可重入);
    - 领取场景: 抛 **140121**(活动奖品不在有效期内,不可发放)。
  - 尚有窗口未结束的行(未开始/窗内有货) → 保持预占行 state=0 等待(既有语义, 签约后库存回补可领取)。

### 2.3 使用(新增过期闸)

- 生效成功时: 券行回写 `expireTime = 所发档位 activityitem.endTime`(复用 `decorationactivityitem.expireTime` 既有列, 该列此前仅通用核销 140058 使用, 阶梯引擎从未写入)。物品档未配 endTime 则不写(不设限)。
- `saveScaleDetails`: state=2 校验后新增 `expireTime != null && expireTime < now` → 抛 **140122**(活动奖品已过期,不可抵扣)。fail-closed 双保险。
- 选券数据源 `queryDecorationActivityItemForScale`: 过滤已过期行(前端不展示, 服务端 140122 兜底)。
- 有效期展示(拍板5: 都展示): 维护页列表/表单、decoration4detail 详情面板券行、salesPayment 收款选券区, 三处均展示 expireTime(未配=不显示)。

## 3. 闭环缺陷修复(上版第7节 + 新排查)

### 3.1 退款回退券(拍板1: 仅全退/倒单回退, 部分退款不回退; 口径=salespayment 层)

**现状缺陷**: 券消耗(7)后, 退款链路不回退券与配比明细 → 客户退了钱丢了券。

**回退触发条件(定案, 2026-11-24 口径修正)**: `refundSalesPayment` 执行退款行时, 退款行 `type ∈ {TYPE_DEPOSITREFUND_INT(7 定金退款), TYPE_NOTDEPOSITREFUND_INT(8 非定金退款)}` 才回退——全退/倒单是 **salespayment(主材销售款项)层语义**(定金退款创建流程本身即置销售单废单 WAST), **与装修单状态无关**; `TYPE_REFUNDS_INT(4 退货退款,部分)` / `TYPE_MAKEAREFUND_INT(5)` / `TYPE_VOUCHERREFUND_INT(6)` 一律**不回退**。

**回退动作**:

1. `DecorationScaleDetailPO` 新增 `STATUS_INVALID_INT = 1`(作废);
2. `DecorationScaleDetailDao` 新增 `queryDecorationScaleDetailValidByOrderId(orderId)`(status=0 列表);
3. `refundSalesPayment` 在 `updateDecorationForSaleScale` **之前**插入回退钩子(私有方法):

```
restoreLadderScaleDetails(orderId, refundType, operater):
  if refundType not in {7, 8}: return          // 部分退款不回退(拍板1)
  for detail in queryDecorationScaleDetailValidByOrderId(orderId):
    detail.status = 1, comment += "全退回退"
    券行 = dao.get(detail.daiId)
    if 券行.state == 7:
       券行.state = 2(已领), content += " 全退回退:<销售单号>"
       记 decorationactivityrecord(STATUS_RECEIVE, "全退回退")
```

4. **配比自动修正**: 置 status=1 后, `amountDecorationScaleDetailForScale`(只圈 status=0)自然剔除, 钩子在重算调用之前 → `materialPaidup` 同事务自动纠正;
5. **守卫自动放行**: 回退后 `countDecorationScaleDetailByOrderId/ByDaiId`(均只圈 status=0)归零 → 每单一张/一券一用守卫对"再收款用券"自然放行, 无需改守卫;
6. **幂等/并发**: 只取 status=0 行 + 券行仅 7 条件转移, 同一 daiId 行锁串行化, 重复/并发回退安全;
7. **cancel 双路径 140119 守卫保留不动**(INITIAL 态本就不可携带明细, 守卫语义不变);
8. 回退后的券若已过 expireTime → 仍回 2 已领, 但被 §2.3 使用闸 fail-closed 拦截。

### 3.2 装修单退单/废单的券处理 → 暂不处理(2026-11-24 口径修正)

**decoration 层的退不考虑退回**: 装修单废单(5)/终止(6)时券行不做任何回收动作——已领(2)/预占(0)随死单挂起(本单一致守卫天然防他用), 消耗(7)券行仅随 salespayment 层全退(§3.1)回退, 不判装修单状态。不设 `obsoleteDecoration`/`terminalDecoration` 钩子。

预留口径(后续若做再立项): 废单 `DecorationServiceImpl.obsoleteDecoration`(:1493, setter :1523)、终止 `terminalDecoration`(:1539, setter :1653) 双钩子; 已领回收时 `awardstock.num += 1000` 库存回补(2026-11-24 已拍"回补", 届时按此实施); 已验证 seiya 同步无旁路直写。

### 3.3 预占档≠实发档 → 口径确认 + 展示补全

水位预占、结算按瞬时库存定档是**设计内行为**(并发安全的前提)。调整仅展示层: 详情页面板显示实发行与预占失效行的降级说明(content 已有"(预占档清零降级)"), 面板补有效期列(拍板5)。不改引擎逻辑。

### 3.4 num 毫单位 → 不改存储, 沉淀口径

券行/awardstock 均按毫存(1张=1000毫), 与额度券口径对齐。改动存储牵动抽奖/额度券三套业务, 风险大于收益, **不做**。沉淀标准盘点 SQL(÷1000 展示)附于本方案, 运维/导出统一引用。

### 3.5 登记不做项(拍板4)

| 项 | 处置 |
|---|---|
| 过期预占行定时清扫 | **先不做**(拍板4)。窗口结束后 state=0 行滞留, 结算时点判定已覆盖主路径; 若后续配置高频换窗活动再评估 |
| 预占后窗口关闭前抢签的秒级并发 | 接受, 口径=以生效事务时刻为准 |
| 回退钩子依赖退款人权限 | 接受, 退款本身为受控操作 |

## 8. 验证口径

1. 物品配窗: 窗内预占/签约/收款全链通; 全窗外预占 140117; 预占后窗口过→签约失效"有效期外失效"→单未死可重新参与;
2. 降级: 预占高档窗闭+低档窗内有货→签约发低档; 全窗结束→签约不阻断+失效 / 领取 140121;
3. 未配窗物品: 行为零变化(回退活动窗), 存量活动回归;
4. 选品过滤: 业务侧 6 处窗外 type=30 不展示、其余类型照常; 维护页全部可见可编辑;
5. 生效回写 expireTime: 收款选过期券 140122, 选券列表不展示; 三处展示位有效期正确;
6. 退款回退: 全退(7/8)→券 7→2 可再用、detail=1、`materialPaidup` 重算正确; 退货退款(4)→券/detail 不动; 装修单废单/终止不触发任何回收; 重复退款不重复回退;
7. cancel 双路径: INITIAL 态照常删行, 140119 守卫不触发;
8. 并发: 两请求同时结算抢最后一张(原子扣减, 一胜一降级); 预占与窗口结束秒级并发按事务时点。
