# 辅料单配送标识(delivery)方案

> 版本: v1.0 已落码(2026-11-05, 六项拍板已收敛)
> 模块: data(辅材档案) + inventory(辅料单)
> 参照系: 费用链参照 accessoriescharge 既有批次(2026-10-30, 3d263f6dd); 费用查看参照外辅 occcessories4view
> 状态: 已落码, jar 已构建待部署

---

## 1. 需求与语义

三处 `delivery` 字段(TINYINT, 0自配 1配送), 一条语义链:

```
data.aoods.delivery(档案级) ──创建时按caid服务端快照──▶ accessoriesitem.delivery(项级)
                                                          │按项汇总(存在需配送项)
                                                          ▼
                                        accessories.delivery(主单标识, 创建弹窗确认, 列表可切换)
```

## 2. 拍板记录(2026-11-05)

| # | 议题 | 拍板 |

| 6 | 存量数据 | 默认自配(0)不回填 |

## 6. 已知边界与存量兼容

- 存量单 delivery=0(自配): 出库闸自动豁免, 出库行为与加列前完全一致; 列表可手动"改配送"让闸生效;
- 老版 app 创建不传 delivery: 服务端按项推导兜底;
- 外辅参照时发现的既有 bug(本批不动外辅): `queryOccessoriesCharge` tranargs 含 num, accReduce 无跳过名单会把响应 num ÷1000, 外辅费用查看弹窗数量/小计疑似千倍偏差, 待另单确认;
- 授权: 新行按钮("改配送/改自配"、"费用")无 company=0 回退, 需按 70 号模板逐公司插 right 行(模板式, 勿整批)。
