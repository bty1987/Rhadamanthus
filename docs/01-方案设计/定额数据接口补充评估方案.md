# 定额数据接口补充评估(辅料单/工费清单 → data.normrice / data.normood)

> 结论先行: **两个接口可以补数, 但存在一个结构性缺口**。接口粒度是"装修单级汇总"(单×节点类型 / 单×定材),
> 而 data.normrice / data.normood 的锚是"报价项"(qiid), **接口无报价项维度是第一缺口**;
> 辅料接口(nid=ERP定材ID)映射基本可用, 工费接口返回节点总额、R 侧存的是单价(trannum×num×salary), 差"÷工程量"一步。
> 建议向上游补报价项维度后再实施; 调用设施可复用 fl-sync 统一验签(DecorationActivityCostServiceImpl 同款 appId=erp_project_sync)。
> 本文档仅为评估, 不动代码。

## 2. R 侧现状

### 2.1 目标两表(注意: 实际在 **data** 库, 非 quotation 库)

- `data.normrice` 定额工费: npid / **qiid**(→报价项) / **cnid**(→施工节点) / unit / trannum(换算系数) / **salary(单位工费)** / stuff / status(0有效 1作废)
- `data.normood` 定额材料: ngid / **qiid** / **nid**(→data.noods 定材) / name / normunit / normnum(定额数量) / storeunit / storenum(库房数量) / price / status

现有写入链路唯一: 报价项创建时 qfid>0 三段复制 `cormrice/cormood/cormtime(qfid) → normrice/normood/normtime(qiid)`(ded8d44a9);
后台另有 `addNormrice/deleteNormrice` 手工维护入口(data/quotation NormriceAction)。
即: **没挂规格(qfid=0)的报价项, 定额为空**, 这是"补数"的主要受益面。

### 2.2 下游消费(补数目的所在)

- 单据层: `quotation.normtion`(定额清单单据头: orderId+qid+moodTotal/mriceTotal+打印次数) + `quotation.normriceitem/normooditem`(实例:
  qid/sid/areaId/quoteId/qiid/npid/ngid/type 0报价 1扩项 2增减 3定额/normtype/atttype/num/status/confirmer)
- **工人工资**: WorkerSalaryServiceImpl → `normriceItemDao.amountNormriceItemForSalary(qid, cnid)` 按节点合计工费
- **辅料管控**: inventory AccessoriesItemServiceImpl → `normoodItemDao.amountNormoodItem(qid, nid)` 按定材合计需求量
- 实例工费公式(前端 normtionPart.js:649): `合计 = trannum × num(报价项工程量) × salary`
  → **normrice.salary 是"单价", 接口 amount 是"节点总额"**, 两者不是同一个量纲。

### 2.3 锚点映射链(拉数后怎么挂)

```
erpOrderCode (高概率 = R 装修单 orderId, 格式吻合 yyMMdd+序号, 口径待确认)
  → quotation.orderId (每装修单一份报价副本; 注意版本 quotationVersion, 取当前生效版本)
  → quotationItem (qiid)
  → data.normrice / data.normood
cnid: 接口 id(erpId串) → data.constructionNode (注意 company 分册, name 匹配须加公司过滤)
nid : 接口 nid → data.noods.nid (pnid: 0=集团行, >0=公司引用行; 直挂需校验公司归属)
```

## 3. 字段对照与缺口(定级)

### 3.1 工费 → data.normrice

| 接口 | R 字段 | 判定 |
|---|---|---|
| id(erpId串) | cnid | ⚠️ 需确认"转换后的erpId"= constructionNode.cnid? cnid 还是集团 pcnid? 须按公司分册校验 |
| name(nodeTypeName) | (参考) | 可兜底按名称匹配 constructionNode.name(须加公司过滤), 名称漂移风险 |
| amount(节点总额) | salary(单价) | 🔴 结构性: 需 ÷(trannum×工程量) 才是 salary, 无报价项维度就算不出; 或落"总额行"(num=1)改语义, 不推荐 |
| — | unit / trannum | 缺, 可取报价项单位 / 置 1 |
| — | stuff | 缺, 沿复制链惯例置 0 |
| — | **qiid** | 🔴 **死结: 接口无报价项维度** |

### 3.2 辅料 → data.normood

| 接口 | R 字段 | 判定 |
|---|---|---|
| nid | nid | ✅ 直接是 ERP 定材 ID, FK 可直挂(校验公司归属) |
| name | name | ✅ |
| quantity | normnum 或 storenum | ⚠️ 双数量口径(定额数量/库房数量)取哪个? int 存储量纲换算待抽查实库定标(前端 trannum×num 直乘直显) |
| — | normunit / storeunit | 缺(复制链来自规格维护), 可置空或从规格库反查 |
| — | price | 缺, 可置 0 |
| — | **qiid** | 🔴 **死结同上** |

### 3.3 缺口定级汇总

1. 🔴 **报价项维度缺失**(两接口同): 接口是 单×节点类型 / 单×定材 汇总, 表锚是 单×报价项(×节点/×定材)。
   若上方算数的基础就是 R 报价结构(他们已持 erpId/nodeTypeName/定材ID 字典), 返回里补报价项的 qiid 或编号(no)成本很低;
   否则只能落"整单汇总行", 与表语义错位。
2. 🔴 **工费 amount 总额 vs salary 单价**: 需要每个报价项的工程量与 trannum 才能还原单价; 或明确改落数目标(实例层)。
3. ⚠️ **erpId 转换规则 + 公司分册归属**(noods/constructionNode 均按 company 分册, 引用行 pnid>0 名称是集团快照)。
4. ⚠️ **辅料双数量口径**(normnum/storenum)+ int 量纲(需抽查现网行定标)。
5. ⚠️ **版本与覆盖口径**: 报价多版本算哪版? 增减项/扩项(normriceitem type 1/2)是否含在返回内? 已有定额(qfid 复制链)的单是否跳过(幂等)?

## 4. 可选落地路径(供未来实施参考, 本次不动代码)

- **路径A(推荐)**: 上游补报价项维度 → 逐单拉取落 data.normrice/normood(挂 qiid), 走现有 normtion 定额清单生成链。
  触发点建议 = 报价确定/开工前; 幂等守卫 = 该单已有定额行则跳过或作废重写(status=1)。
- **路径B(不依赖上游改造)**: 接口数据直接生成 normtion 单据+实例(工费: 每节点一行; 辅料: 每定材一行),

  data.normrice/normood 保持空。改动小但绕开模板层, 工费按"总额行"语义处理, 需与工资核算口径核对。
- **路径C(仅补缺)**: 只对"无规格(qfid=0)→无定额"的装修单按接口补数, 已有定额的单不动。与 A/B 可叠加。
- **调用设施**: 复用 fl-sync 统一验签 HTTP(参考 DecorationActivityCostServiceImpl: appId=erp_project_sync 硬编码,

  两个新接口的 sign 具体规则以对方文档为准("sign 为 appId 对应密钥"描述含糊, 需确认是否同一套验签)。

### 7.2 落行规则(2026-11-18 模型修正: 实例层直存, 详见 7.6)

1. **落表**: quotation.normriceitem / quotation.normooditem(normtion 单据明细实例)——三方定额不关联报价项
   (这类单报价无明细), 以 normtion 单据(qid)锚单; data.normrice/normood 两表无订单维度, 不再使用。
2. **公共字段**: qid/sid=报价 qid, qiid=areald=quoteld=0, npid(ngid)=0, type=3 定额行(幸存 makeNormtion
   重跑 disable——两级 disable 均带 `type != 3`), atttype=0, status=0(INIT)。
3. **工费行**: cnid=接口id(节点字典校验), normtype=1 附加确认流(确认后计工资), trannum=0 总额行
   (salary=amount×1000 厘, 不乘工程量), num=0。
4. **辅料行**: nid=接口nid(定材字典校验), normtype=0 材料, normnum=storenum=quantity×1000 毫(直存实际量)。
5. **仅补缺**: 工费同 cnid(INIT+CONFIRMED)/辅料同 nid(INIT) 现存行跳过; 三方同 id 重复取末行。
6. **fail-closed**: 字典查不到/金额数量缺失或 ≤0 → 200135; 接口失败/空 data → 200133/200134; 未配置 → 200132。
7. **normtion 单据头**: 判断不存在进行创建(qid+orderId+creater+createTime)。

- **工费行 normriceitem**: cnid=接口id(施工节点字典校验), name=节点名, normtype=1(附加确认流——confirmNormriceItem 确认后计入 `amountNormriceItemForSalary`), trannum=0(总额行, salary=amount×1000 厘, 工资 SQL/前端原生兼容不乘工程量), num=0
- **辅料行 normooditem**: nid=接口nid(定材字典校验), normtype=0(材料), normnum=storenum=quantity×1000 毫(实例层直存实际量, `amountNormoodItem` 无 type 过滤 INIT 即计)
- **仅补缺**: 工费按 queryNormriceItemByType(qid, 3)(INIT+CONFIRMED) 同 cnid 跳过; 辅料按 queryNormoodItem(qid)(INIT) 同 nid 跳过; 三方同 id 重复 log.warn 取末行
- **fail-closed**: cnid/nid 字典查不到、amount/quantity 缺失或 ≤0 → 200135; 全链不报错时数据即可被 accessories(辅料管控) 与 workersalary(工资核算, 经确认流) 消费
