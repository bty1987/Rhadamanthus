# 方案-前端样式规范逐步适配计划

> **状态**:提案(2026-10-26),待拍板后排期;未拍板不动代码。
> **规范依据**:《12-规范标准/前端页面样式规范与风格说明.md》(来源 view-decoration-pc + view-yy-pc 驾驶舱,本文不重复色值)。
> **与迁移线的关系**:本项目已有 docs/mover/ 迁移规划(jQuery/Bootstrap → view-decoration-pc 同款 Vue3+TS+Arco,四大模块 24 核心页,190-255 人天)。**样式适配不另起炉灶,全程搭迁移线便车**——迁走的页面天然落进新风格;留在老站里的页面只做低成本皮肤对齐;报表平台单列专项。
> **范围红线**:存量 667 个 jQuery 页面**不做页面级样式翻新**(投入产出比不成立);一切存量改动限定在皮肤层(css/主题文件),不碰 DOM 与 js 结构。

---

## 一、现状评估摘要

| 维度 | 现状 | 与规范的差距 |
|---|---|---|
| 存量前端 | Ace Admin + jQuery 1.x + Bootstrap 3 + LayUI 的 MPA,27 业务模块,**667 个视图页**、753 个 js | 结构性差距,不可弥合,只能等迁移或皮肤对齐 |
| 主题机制 | 已有多皮肤(clear/dark/metro + index-* 变体),css/ 下主题文件独立 | ✅ 有现成皮肤通道,新增一套"现代主题"皮肤成本可控 |
| 自定义样式 | css/main.css 为主,com.* 框架封装(Api/Validator/Printer/Condition) | 无 token 体系,色值散落 |
| 报表平台 | metric_* + echarts(altogether 资产) | 配色各自为政,无统一主题;数字格式化口径不一 |
| 迁移线 | mover/ 11 篇文档就绪,目标栈=view-decoration-pc 同款(Arco 2.57) | 迁移验收标准里**没有样式检查项**——本计划补上 |
| 高频痛点 | 高管/老板常看的汇总页读数偏小、口径不一 | 驾驶舱可读性底线未落地 |

## 二、适配策略(三条线,一张表)

| 线 | 对象 | 动作 | 成本 |
|---|---|---|---|
| A 迁移线 | mover 规划的 24 核心页 | 按既有路线迁入新前端,样式规范作为**迁移验收项**逐页过 | 0 增量(搭车) |
| B 皮肤线 | 未迁移存量页 | 新增一套"arco 对齐"主题皮肤(主色/表头/边框/按钮/字级对齐),切默认主题 | 低(纯 css) |
| C 看板线 | 报表平台 + 高管看板页 | 引入驾驶舱规范:chart-theme 低饱和主题 + 指标卡组件 + 数字格式化统一 | 中(逐页) |

优先级:**C 的高管页 > A(搭车,随迁移节奏)> B(最低配起步)> 其余**。理由:高管页是老板每天看的脸面,读数小、口径乱是当前最疼的;A 反正要做;B 是视觉统一的最大公约数;其余存量页保持现状不动。

## 三、分阶段计划

### 阶段 0:基线与拍板(0.5 天,一次性)

1. 现状截图基线:核心 10 页(4 模块代表页 + 报表 3 页 + 首页)整页截图归档 `docs/screenshots/style-baseline/`,供适配前后对比。
2. 三个拍板项(不拍板不开工):
   - 主色:默认 `#165dff`(Arco arcoblue-6,与 view-decoration-pc 一致)——确认是否保留品牌色调整空间;
   - **涨跌语义分场景口径**:业绩/销售页用"红涨绿跌"、管理线/达成率页用"好绿差红"(见规范 3.4)——确认;
   - 高管页可读性底线:主数≥32px、环比≥16px 加粗、标注≥12.5px——确认。
3. 明确本计划的验收归属人(前端负责人)。

### 阶段 1:基座建设(2-3 天)

1. **B 线皮肤**:`css/` 新增 `modern.css`(挂在现有主题机制上,不动 main.css),只做五件事——主色变量、表头底 `#FAFAFA`、输入/筛选框边框 `#dbdbdb`+4px 圆角、按钮尺寸/圆角、卡片区阴影 `0 1px 10px rgba(38,52,74,.12)`。以"切了像新站、不切无影响、可一键回退"为验收。
2. **C 线主题资产**:`js/com/` 下新增 `chart-theme.js`(照抄 view-yy-pc `chart-theme.ts` 色板与规范,echarts registerTheme)与 `format.js`(万元两位小数/率 1 位/带符号/空值 `—`/tabular-nums 工具函数),供报表页统一调用。
3. 拍板产物落档:阶段 0 结论写进规范文档附录。

### 阶段 2:范例页双试点(3-5 天)

1. **业务页范例**:选 1 个高频列表页(建议付款或装修单列表)做"皮肤线深度版"——筛选栏/表格/分页/抽屉细节对齐规范 2.5-2.6,作为存量页改造的参照实现与工作量标尺。
2. **看板页范例**:选 1 个高管常看报表页(建议经营汇总类 metric 页)按驾驶舱规范重构——指标卡(主数 32px/标注 16px 加粗/分档色)+ chart-theme + 英雄头部可选。**此页即 C 线的验收样板**。
3. 两页上线观察一周(收集"看着累不累/数字清不清楚"的高管反馈,这是这套规范的最终裁判)。

### 阶段 3:制度收口(1 天,随阶段 2 并行)

1. mover 各模块验收清单增加"样式检查项"(对照规范第二/三章的速查表:色板/字号层级/页面骨架/组件约定),迁移一页验一页。
2. 新页面准入规则:今后 WebContent 内**任何新建页面**(不迁走的)按皮肤线规范写,禁止引入新的自造色值。
3. 报表新增页强制走 chart-theme + format.js,禁页面内散写色板。

### 阶段 4:报表平台批量看板化(滚动,按页排期)

- 按高管查看频率排优先级,逐页按范例改造(每页 0.5-1 天);先做月度经营会涉及的 5-8 页,其余随改随排。
- 每页改造前截对比图,改造后走阶段 3 的样式检查项。

### 阶段 5:长尾收口(远期,随业务节奏)

- 高频存量页(按埋点/使用频率 Top 20-30)按范例页模式滚动皮肤对齐;
- 其余页面保持现状,等迁移线自然消化;
- 迁移完成后退役皮肤线(css/modern.css 归档)。

## 四、验收标准

1. 阶段 1:切换 modern.css 前后所有存量页功能回归零差异(纯视觉);一键回退可用。
2. 阶段 2 看板范例:主数/标注/分档色/数字格式化四项全部符合规范 3.3/3.4/3.7;高管主观确认"看得清"。
3. 阶段 3 起:任何新页面/迁移页面,样式检查项通过率 100%(色值取值唯一来源=规范文档)。
4. 全程:存量页无一处因样式改动出现布局错位/功能回归(截图对比留档)。

## 五、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 皮肤线与 Bootstrap 3 样式互相覆盖导致局部错位 | 中 | modern.css 只做变量级/组件级覆盖,逐页走查阶段 2 范例先行;出问题切回旧主题即回退 |
| 双轨期新旧页面视觉不一致被吐槽"半新半旧" | 中 | 皮肤线优先对齐主色/边框/表头三个最高频视觉锚点,先求"像一家人";完整统一交给迁移线时间 |
| 报表页改造动到取数逻辑引入数据事故 | 中 | C 线只动展示层(主题/格式化/卡片段),禁止改 SQL/接口;改造页数值与旧版逐格核对后再上线 |
| 语义色两套口径(红涨绿跌 vs 好绿差红)被混用 | 低 | 阶段 0 拍板写死场景清单;样式检查项里专列一条 |
| 迁移线排期本身未启动导致 A 线落空 | 低 | 本计划不依赖 A 线启动;A 线启动时验收清单即插即用 |

## 六、开放问题(实施前确认)

1. modern.css 是否启用为默认主题,还是先灰度给内部账号试用?
2. 报表平台第一期改造页清单(建议:月度经营会高频 5-8 页,由经营线确认)。
3. 高管驾驶舱类新页是否需要英雄头部范式(渐变横幅),还是保持朴素指标卡墙?
4. 存量页水印(审计追溯)在皮肤线中是否同步补齐(view-decoration-pc 有全站水印,存量无)。
