## 📖 知识库概述

项目知识库是一个集中管理项目核心知识的 Markdown 文件，位于：

## 🎯 使用方式

### 对 AI 来说（自动）

每次对话时，AI 会自动：
1. 读取项目根目录的 `CLAUDE.md`
2. 发现知识库引用：`docs/KNOWLEDGE_BASE.md`
3. 自动读取知识库内容
4. 基于知识库内容回答问题

**示例对话**:
```
用户: 如何添加新的业务模块？

AI（参考知识库后）:
根据项目知识库，添加新模块的步骤如下：
1. 创建包结构...
2. 创建实体类...
...
```

### 对开发者来说

#### 方式1: 自然提问（推荐）

直接向 AI 提问，它会自动参考知识库：

```
如何处理客户手机号加密？
如何实现分页查询？
工具类应该放在哪里？
```

#### 方式2: 明确引用知识库

如果需要强调，可以明确提到知识库：

```
根据知识库中的规范，我应该如何创建一个新的 Action？
```

## 🚀 进阶用法

### 1. 创建模块级知识库

对于大型模块，可以创建独立的知识库文件：

```
docs/KNOWLEDGE_BASE.md          # 项目级知识库
docs/decoration/KNOWLEDGE.md    # 装饰模块知识库
docs/payment/KNOWLEDGE.md       # 支付模块知识库
```

在主知识库中引用：
```markdown
## 模块知识库

- [装饰订单模块](docs/decoration/KNOWLEDGE.md)
- [支付模块](docs/payment/KNOWLEDGE.md)
```

### 2. 使用 Slash Command

创建自定义命令快速加载特定知识：

**文件**: `.claude/commands/kb.md`
```markdown
---
description: 显示项目知识库目录
---

请列出项目知识库 (docs/KNOWLEDGE_BASE.md) 的目录结构
```

**使用**: `/kb`

### 3. 集成外部文档

如果知识库太大，可以引用外部文档：

```markdown
## 详细文档

完整的 API 文档请参考：[docs/API.md](docs/API.md)
前端架构请参考：[WebContent/CLAUDE.md](WebContent/CLAUDE.md)
```

## ❓ 常见问题

### Q1: AI 为什么没有参考知识库？

**可能原因**:
1. 知识库文件路径错误
2. 知识库内容不相关
3. 问题本身不需要参考知识库

**解决方案**:
- 检查 `CLAUDE.md` 中的引用路径是否正确
- 明确告诉 AI：`请参考知识库回答`
- 检查知识库内容是否包含相关信息

### Q2: 知识库文件太大怎么办？

**解决方案**:
1. 拆分为多个文件（模块级知识库）
2. 只保留核心信息，详细信息链接到其他文档
3. 使用目录结构快速定位

### Q3: 如何确保 AI 一定能看到知识库？

**最佳实践**:
1. ✅ 在 `CLAUDE.md` 中显式引用
2. ✅ 在知识库开头添加"重要提示"
3. ✅ 使用清晰的标题结构
4. ✅ 保持内容简洁相关

### Q4: 知识库支持哪些格式？

**支持的格式**:
- ✅ Markdown (推荐)
- ✅ 代码块
- ✅ 表格
- ✅ 列表
- ✅ 链接
- ⚠️ Mermaid 图表（部分支持）
