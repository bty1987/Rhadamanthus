# R项目 敏感数据加密方案 (调整版)

## 一、现状分析

经过代码排查，当前项目的加密情况如下：

```
现有加密机制:
  算法:   AES/CBC/PKCS5Padding
  密钥:   encryptKey=b4d617b336124c63 (16字节, 写死在sysconfig.properties)
  IV:     encryptIv=b4d1a58a416957a5 (16字节, 写死在sysconfig.properties)
  工具类: FormatUtil.encodePhone() / decodePhone()
  引擎:   AESHelper.encrypt() / decrypt()

当前已加密的字段:
  customer.phone       -- 已加密 (通过FormatUtil)
  customerphone.phone  -- 已加密 (通过FormatUtil)
  user.phone           -- 未加密 (直接存明文)
  customer.identity    -- 未加密 (直接存明文)
  user.identity        -- 未加密 (直接存明文)
```

## 二、存在的问题

1. **加密范围不足**: phone字段已加密，但 identity(身份证号) 字段明文存储
2. **密钥硬编码**: AES密钥和IV直接写在配置文件中，且固定不变
3. **异常处理不安全**: 加解密失败时原样返回明文，等于没有加密
4. **无密钥轮换机制**: 密钥写死后无法更换，泄露则全量数据暴露
5. **user表未加密**: user.phone / user.identity 均为明文存储

## 三、目标字段清单

```
+---------------------------+------------+------------+------------------+
| 表                        | 字段       | 当前状态   | 目标             |
+---------------------------+------------+------------+------------------+
| communion.customer        | phone      | AES加密    | 保留加密(升级)   |
| communion.customer        | identity   | 明文       | 新增加密         |
| communion.customerPhone   | phone      | AES加密    | 保留加密(升级)   |
| communion.user            | phone      | 明文       | 新增加密         |
| communion.user            | identity   | 明文       | 新增加密         |
+---------------------------+------------+------------+------------------+
```

## 四、代码层调整方案

### 第1步: 统一加密工具类

在 `com.fanglin.core.security` 包下新建 `SensitiveDataHelper.java`，替代 FormatUtil 中的加密方法：

```java
// SensitiveDataHelper.java
public class SensitiveDataHelper {

    private static final String ENCRYPT_PREFIX = "ENC(";
    private static final String ENCRYPT_SUFFIX = ")";
    private static final String ENCRYPT_VERSION = "V1"; // 密钥版本号

    // 加密 -- 带版本前缀
    public static String encrypt(String plaintext) {
        if (StringUtils.isEmpty(plaintext)) return plaintext;
        if (isEncrypted(plaintext)) return plaintext; // 已加密不重复加密
        
        try {
            String encrypted = AESHelper.encrypt(
                plaintext,
                KeyManager.getCurrentKey(),
                KeyManager.getCurrentIv()
            );
            return ENCRYPT_PREFIX + ENCRYPT_VERSION + ":" + encrypted + ENCRYPT_SUFFIX;
        } catch (Exception e) {
            throw new RuntimeException("加密失败: " + e.getMessage(), e);
            // 不再静默返回明文!
        }
    }

    // 解密 -- 兼容新旧格式
    public static String decrypt(String ciphertext) {
        if (StringUtils.isEmpty(ciphertext)) return ciphertext;
        
        // 新格式: ENC(V1:xxxx)
        if (isEncrypted(ciphertext)) {
            String inner = ciphertext.substring(
                ENCRYPT_PREFIX.length(), 
                ciphertext.length() - ENCRYPT_SUFFIX.length()
            );
            String version = inner.split(":")[0];
            String data = inner.split(":")[1];
            return AESHelper.decrypt(data, KeyManager.getKey(version), KeyManager.getIv(version));
        }
        
        // 旧格式: 纯Base64密文 (兼容存量数据)
        try {
            return AESHelper.decrypt(
                ciphertext,
                KeyManager.getLegacyKey(),
                KeyManager.getLegacyIv()
            );
        } catch (Exception e) {
            // 兜底: 如果解密失败，可能本身就是明文
            return ciphertext;
        }
    }

    // 判断是否已加密(新格式)
    public static boolean isEncrypted(String value) {
        return value != null 
            && value.startsWith(ENCRYPT_PREFIX) 
            && value.endsWith(ENCRYPT_SUFFIX);
    }
}
```

### 第2步: 密钥管理 -- KeyManager

```java
// KeyManager.java
public class KeyManager {
    
    // 旧密钥 (兼容存量数据)
    private static final String LEGACY_KEY = "b4d617b336124c63";
    private static final String LEGACY_IV  = "b4d1a58a416957a5";

    // 新密钥V1 (从环境变量或安全配置读取，不再写死)
    private static final String KEY_V1 = SystemConfig.getString("encryptKeyV1");
    private static final String IV_V1  = SystemConfig.getString("encryptIvV1");

    public static String getCurrentKey() { return KEY_V1; }
    public static String getCurrentIv()  { return IV_V1; }
    
    public static String getKey(String version) {
        switch (version) {
            case "V1": return KEY_V1;
            default: throw new RuntimeException("未知密钥版本: " + version);
        }
    }
    
    public static String getLegacyKey() { return LEGACY_KEY; }
    public static String getLegacyIv()  { return LEGACY_IV; }
}
```

## 五、存量数据迁移方案

这是最关键的部分。由于数据库中存在三种状态的数据：

```
状态A: customer.phone / customerphone.phone -- 已AES加密(旧密钥，无前缀)
状态B: user.phone -- 明文
状态C: customer.identity / user.identity -- 明文
```

### 迁移策略: 停机一次性迁移 (推荐)

**适用场景**: 可以安排维护窗口，暂停服务几小时。

#### 迁移脚本 (Python)

```python
#!/usr/bin/env python
# migrate_sensitive_data.py
# 存量敏感数据加密迁移脚本

import pymysql
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad, unpad
import base64
import sys

# ========== 配置 ==========
DB_HOST = 'your-db-host'
DB_PORT = 3306
DB_USER = 'root'
DB_PASS = 'your-password'
DB_NAME = 'communion'

# 旧密钥(兼容已加密数据)
LEGACY_KEY = b'b4d617b336124c63'
LEGACY_IV  = b'b4d1a58a416957a5'

# 新密钥V1
NEW_KEY = b'xxxxxxxxxxxxxxxx'  # 32字节 AES-256
NEW_IV  = b'xxxxxxxxxxxxxxxx'  # 16字节

BATCH_SIZE = 500
ENCRYPT_PREFIX = "ENC(V1:"

# ========== AES加解密 ==========
def aes_encrypt(plaintext, key, iv):
    cipher = AES.new(key, AES.MODE_CBC, iv)
    padded = pad(plaintext.encode('utf-8'), AES.block_size)
    encrypted = cipher.encrypt(padded)
    return base64.b64encode(encrypted).decode('utf-8')

def aes_decrypt(ciphertext, key, iv):
    raw = base64.b64decode(ciphertext)
    cipher = AES.new(key, AES.MODE_CBC, iv)
    decrypted = unpad(cipher.decrypt(raw), AES.block_size)
    return decrypted.decode('utf-8')

def is_old_encrypted(value):
    """判断是否是旧格式加密数据(纯Base64)"""
    if not value or len(value) < 10:
        return False
    try:
        decoded = base64.b64decode(value)
        aes_decrypt(value, LEGACY_KEY, LEGACY_IV)
        return len(decoded) > 0
    except:
        return False

def is_new_encrypted(value):
    """判断是否是新格式加密数据"""
    return value and value.startswith("ENC(V1:")

def migrate_value(value, force_encrypt=False):
    """
    将任意格式的值迁移到新格式
    force_encrypt=True: 无论什么格式都重新加密(用于密钥轮换)
    """
    if not value or len(value.strip()) == 0:
        return value
    
    value = value.strip()
    
    # 已经是新格式，不处理(除非强制重新加密)
    if is_new_encrypted(value) and not force_encrypt:
        return value
    
    # 先解密到明文
    plaintext = value
    if is_old_encrypted(value):
        plaintext = aes_decrypt(value, LEGACY_KEY, LEGACY_IV)
    
    # 用新密钥加密，加版本前缀
    new_encrypted = aes_encrypt(plaintext, NEW_KEY, NEW_IV)
    return ENCRYPT_PREFIX + new_encrypted + ")"

# ========== 迁移逻辑 ==========
def migrate_table(conn, table, id_col, columns):
    """通用表迁移"""
    cursor = conn.cursor(pymysql.cursors.DictCursor)
    
    # 统计总数
    cursor.execute(f"SELECT COUNT(*) as cnt FROM {table}")
    total = cursor.fetchone()['cnt']
    print(f"\n[迁移] {table} 总计 {total} 条记录，处理列: {columns}")
    
    migrated = 0
    skipped = 0
    errors = 0
    
    offset = 0
    while offset < total:
        cursor.execute(
            f"SELECT {id_col}, {', '.join(columns)} FROM {table} "
            f"ORDER BY {id_col} LIMIT %s OFFSET %s",
            (BATCH_SIZE, offset)
        )
        rows = cursor.fetchall()
        
        for row in rows:
            row_id = row[id_col]
            updates = {}
            
            for col in columns:
                old_val = row[col]
                if not old_val or len(str(old_val).strip()) == 0:
                    continue
                new_val = migrate_value(str(old_val))
                if new_val != old_val:
                    updates[col] = new_val
            
            if updates:
                try:
                    set_clause = ", ".join([f"{k}=%s" for k in updates.keys()])
                    values = list(updates.values()) + [row_id]
                    cursor.execute(
                        f"UPDATE {table} SET {set_clause} WHERE {id_col}=%s",
                        values
                    )
                    migrated += 1
                except Exception as e:
                    errors += 1
                    print(f"  [ERROR] {table}.{id_col}={row_id}: {e}")
                    conn.rollback()
            else:
                skipped += 1
        
        conn.commit()
        offset += BATCH_SIZE
        progress = min(offset, total)
        print(f"  进度: {progress}/{total} (迁移:{migrated} 跳过:{skipped} 错误:{errors})")
    
    print(f"  [完成] {table}: 迁移{migrated}条, 跳过{skipped}条, 错误{errors}条")
    return migrated, skipped, errors

def main():
    conn = pymysql.connect(
        host=DB_HOST, port=DB_PORT, user=DB_USER, 
        password=DB_PASS, db=DB_NAME, charset='utf8mb4'
    )
    
    try:
        total_migrated = 0
        total_errors = 0

        # 1. customer.phone (已加密→重新加密+版本前缀)
        m, s, e = migrate_table(conn, 'customer', 'cid', ['phone'])
        total_migrated += m; total_errors += e

        # 2. customer.identity (明文→加密)
        m, s, e = migrate_table(conn, 'customer', 'cid', ['identity'])
        total_migrated += m; total_errors += e

        # 3. customerPhone.phone (已加密→重新加密+版本前缀)
        m, s, e = migrate_table(conn, 'customerPhone', 'cpid', ['phone'])
        total_migrated += m; total_errors += e

        # 4. user.phone (明文→加密)
        m, s, e = migrate_table(conn, 'user', 'uid', ['phone'])
        total_migrated += m; total_errors += e

        # 5. user.identity (明文→加密)
        m, s, e = migrate_table(conn, 'user', 'uid', ['identity'])
        total_migrated += m; total_errors += e

        print(f"\n{'='*50}")
        print(f"迁移完成! 总计迁移: {total_migrated}条, 错误: {total_errors}条")

    finally:
        conn.close()

if __name__ == '__main__':
    main()
```

### 备选方案: 不停机双写迁移

如果无法停机，可以用渐进式方案：

```
步骤1: 部署兼容代码
  - 新代码同时支持旧格式(纯Base64)和新格式(ENC(V1:xxx))的读取
  - 新写入的数据使用新格式加密
  - 旧数据暂时不动

步骤2: 后台迁移存量数据
  - 启动后台脚本，分批读取未迁移的记录
  - 解密→重新加密→写回
  - 每批100条，间隔200ms，避免影响线上性能
  - 通过字段前缀 "ENC(V1:" 判断是否已迁移

步骤3: 验证完成
  - 确认所有记录都已迁移到新格式
  - 移除旧格式兼容代码
```
