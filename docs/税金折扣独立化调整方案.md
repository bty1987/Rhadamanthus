# 税金折扣独立化调整方案

> 创建时间：2026-05-21
> 项目：Rhadamanthus（装企信息平台）
> 模块：报价系统 - 税金计算

---

## 一、背景

当前系统税金折扣与管理费折扣耦合，税金自身无法独立控制是否打折。需要将税金折扣从管理费折扣中解耦，支持 5 种独立的税金模式。

### 现有枚举

| 值 | 含义 | 行为 |
|---|---|---|
| 0 | 无税金 | 税金为0 |
| 1 | 管理税金 | 基数不含管理费，税金跟随管理费折扣 |
| 2 | 总额税金 | 基数含管理费，税金不打折 |

### 问题

1. 税金是否打折由管理费折扣决定，无法独立配置
2. 无法实现"管理税金但不打折"或"总额税金但打折"的场景

---

## 二、新枚举定义

| 值 | 含义 | 计算基数 | 税金打折 |
|---|---|---|---|
| 0 | 无税金 | — | — |
| 1 | 管理税金（打折） | 不含管理费 | × discount |
| 2 | 总额税金（打折） | 含管理费 | × discount |
| 3 | 管理税金（不打折） | 不含管理费 | 不打折 |
| 4 | 总额税金（不打折） | 含管理费 | 不打折 |

### 3.4 统一计算逻辑模板

```javascript
// 税金计算统一模板
var _taxfee = 0, _dtaxfee = 0;

if (_taxDiscount == 0) {
    // 无税金
    _taxfee = 0;
    _dtaxfee = 0;
} else {
    var _taxBase;
    if (_taxDiscount == 1 || _taxDiscount == 3) {
        // 管理税金：基数不含管理费
        _taxBase = utils.changeThrDecimal(utils.accSub(
            utils.accSub(utils.accSub(utils.accSub(utils.accAdd(
                utils.accAdd(utils.accAdd(_disPrice, _undisPrice), quotePrice
            ), _transfee), preferPrice), managePrefer), advancePrefer
        ), activityProfit));
    } else if (_taxDiscount == 2 || _taxDiscount == 4) {
        // 总额税金：基数含管理费
        _taxBase = utils.changeThrDecimal(utils.accSub(
            utils.accSub(utils.accSub(utils.accSub(utils.accAdd(
                utils.accAdd(utils.accAdd(utils.accAdd(_disPrice, _undisPrice), quotePrice
            ), _transfee), _managefee), preferPrice), managePrefer), advancePrefer
        ), activityProfit));
    }

    _taxfee = utils.changeThrDecimal(utils.accMul(_taxBase, _taxRate));

    // 判断税金是否打折：1和2打折，3和4不打折
    if (_taxDiscount == 1 || _taxDiscount == 2) {
        _dtaxfee = utils.changeThrDecimal(utils.accMul(_taxfee, _discount));
    } else {
        _dtaxfee = _taxfee;
    }
}
```

#### 4.2.6 JS 改造 - 保存逻辑

```javascript
// 税金配置弹窗保存按钮
saveTaxConfig: function() {
    com.focusPage('#saveTaxConfigBtn').click(function() {
        if (com.validate('taxConfigModal')) {
            return false;
        }

        var _taxBase = parseInt(com.focusPage('#taxBaseType').val());     // 1=管理税金, 2=总额税金
        var _taxDisc = parseInt(com.focusPage('#taxDiscountType').val()); // 1=打折, 0=不打折

        // 组合为新的 taxDiscount 枚举值
        var _newTaxDiscount;
        if (_taxBase == 1 && _taxDisc == 1) {
            _newTaxDiscount = 1; // 管理税金（打折）
        } else if (_taxBase == 2 && _taxDisc == 1) {
            _newTaxDiscount = 2; // 总额税金（打折）
        } else if (_taxBase == 1 && _taxDisc == 0) {
            _newTaxDiscount = 3; // 管理税金（不打折）
        } else if (_taxBase == 2 && _taxDisc == 0) {
            _newTaxDiscount = 4; // 总额税金（不打折）
        }

        // 更新税金行的 data-discount 属性
        com.focusPage('#taxCost').find('.discountprice').attr('data-discount', _newTaxDiscount);

        // 重新计算费用
        quo.calculateQuoFees();
        quo.quoModals.$taxConfigModal.modal("hide");

        // 调用后端 API 保存
        var _taxId = com.focusPage('#taxCost').attr('qfaiId');
        var args = {
            "quotationFunctionAreaItem.qfaiId": _taxId,
            "quotation.taxDiscount": _newTaxDiscount,
        };

        com.post(api.quotation.updateQuotationTaxConfig, args, function(res) {
            // 保存成功，已在 calculateQuoFees 中更新界面
        });
    });
},
```

> **注意：** 后端需新增 `updateQuotationTaxConfig` 接口（或复用现有更新接口），接收 `taxDiscount` 参数更新报价记录。

#### 4.2.7 计算逻辑适配

税金计算处（~460-469行）需从 2 分支改为 5 分支，使用统一计算模板（见第三章 3.4 节）。

当前逻辑：
```javascript
// 旧：2 分支，税金打折跟随管理费
if (_taxDiscount == TAX_NODISCOUNT_INT) {  // =1，管理税金
    _taxfee = 管理税金基数 * 税率;
    _dtaxfee = _taxfee * _manageDiscount;  // 跟随管理费折扣！
}
if (_taxDiscount == TAX_DISCOUNT_INT) {    // =2，总额税金
    _taxfee = 总额税金基数 * 税率;
    _dtaxfee = _taxfee;                     // 不打折
}
```

改为 5 分支（枚举值 0-4），税金打折独立于管理费：
```javascript
if (_taxDiscount == 0) {
    _taxfee = 0; _dtaxfee = 0;
} else {
    // 1或3→管理税金基数，2或4→总额税金基数
    if (_taxDiscount == 1 || _taxDiscount == 3) { _taxBase = 不含管理费; }
    if (_taxDiscount == 2 || _taxDiscount == 4) { _taxBase = 含管理费; }
    _taxfee = _taxBase * _taxRate;
    // 1或2→打折，3或4→不打折
    _dtaxfee = (_taxDiscount == 1 || _taxDiscount == 2) ? _taxfee * _discount : _taxfee;
}
```

| 0 | — | 无税金 | 0（不变） |

| 1 | 1（管理费打折） | 税金随管理费打折 | **1**（管理税金打折，不变） |
| 2 | — | 总额税金不打折 | **4**（总额税金不打折） |

## 五、执行顺序

| 步骤 | 内容 | 环境 |
|---|---|---|
| 1 | 后端 Java 加常量（TAX_MANAGE_NODISCOUNT=3, TAX_TOTAL_NODISCOUNT=4） | 开发 |
| 2 | 配置页面改造（quotationVersion + decorationMatching）5个radio | 开发 |
| 3 | 税金小齿轮功能（4个HTML弹窗 + JS齿轮/弹窗/保存逻辑） | 开发 |
| 4 | 计算逻辑改造（8个 JS 文件，2分支→5分支） | 开发 |
| 5 | 功能测试（5 种税金模式 + 各种折扣组合 + 小齿轮交互） | 测试 |
| 6 | 数据迁移 | 测试环境先执行，验证无误后生产执行 |
| 7 | 部署上线 | 生产 |

### 测试要点

1. **小齿轮交互**：点击税金齿轮，弹窗正确回显当前配置，修改后保存正确更新 taxDiscount 值
2. **新报价**：5 种税金模式各创建一个报价，验证计算正确
3. **老报价**：打开迁移后的老报价，验证税金金额未变化
4. **增减项**：增减项中的税金计算正确
5. **扩展项**：扩展项中的税金计算正确
6. **半包折扣**：半包模式下税金打折逻辑正确（独立于管理费折扣）
7. **决算**：决算输出中税金显示正确
8. **多页面一致性**：quotationPart / quotationDetail / quotationWhole / quotetionPart 四个页面行为一致

## 七、风险点

1. **JS 文件改动量大**（8个文件，约 30+ 处），需逐一排查不可遗漏
2. **老数据迁移不可逆**，生产执行前必须在测试环境完整验证
3. **decorationholonomy 表**中 taxDiscount=1 的数据量较大（15,157 条），需确认 manageDiscount 字段分布
4. **quotetion 表**（旧版报价）需要确认 manageDiscount 字段是否存在及数据分布
5. **前端常量引用**（`constant.data().quotationVersion.TAX_*`）需要确认后端 API 返回的 keys 映射是否需要同步更新
