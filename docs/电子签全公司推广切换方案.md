## 一句话结论

**切换粒度定为"模板级"：模板在哪家厂商、合同就在哪家签**——法大大存量模板零影响自然延续，e签宝模板准备好一个切一个，按合同量从高频到长尾渐进迁移；印章授权逐家公司办理；3~4 个月完成高频模板迁移，长尾模板留在法大大长期共存，无需"全量清零"。

## 2. 前置拍板项（✅ 三项已全部拍板，2026-10-22）

### D1. ✅ 模板级路由（用户拍板）

> **用户原话语义：模板是法大大的，签合同的流程就用法大大；反之就使用 e签宝。**

- **按模板定厂商**：`data.contract` 模板行携带厂商标记，生成合同时按模板路由
- 法大大也是自己的控制台模板体系（`GenerateContractParams.templateId`），与 e签宝 docTemplate 同构——"模板在哪家、签在哪家"天然成立
- **代码改造点**（小改）：`routeForCreate` 现按"公司×场景配置"路由，改为**优先读模板行 path 前缀**（`esign://` → e签宝，`fadada://`/无前缀 → 法大大），公司配置降级为默认值。试点已有 `esign://docTemplate` 标记先例
- **迁移策略**：按合同量优先级迁移——高频模板（保密协议 2237 份/年、无理由退承诺 1300+ 份/模板等 Top-N）先迁，长尾低频模板**留在法大大长期共存**，不强求清零。e签宝侧文件生成统一走 docTemplate 重建（试点同款，64 控件模板重建流程已跑通一遍）

### D2. ✅ 印章授权逐家办理（用户拍板：逐个申请和调整）

- autoSign 仅应用主体企业免授权，其余公司由用户逐家向 e签宝申请印章授权
- **已实测确认：授权走已集成的 org-auth-url 接口 + `authorizedScopes:["manage_org_resource"]` 参数**，返回 H5 授权链接，经办人手机自助完成（实名确认→意愿核验→同意授权），**无需逐家找商务**
- **优化：认证+授权可合一**——org-auth-url 带 authorizedScopes 时，未实名的机构打开同一链接会先引导实名再引导授权，一次人工操作完成两件事；ERP 印章认证流程（authSignet）带上范围参数即可一步到位
- **人工量级**：按公司计，每家约 10 分钟、一次性（授权不撤销则永久有效）；客户侧实名签署是每单业务自然环节（客户本来就要签字），不算额外人工
- 单公司 SOP 中固化办理环节（见 §3 阶段 3）；办理进度作为批次推进的台账项

### D3. ✅ 正式版开通与计费（用户拍板：没有问题）

- 正式版/CA/出证/计费预算确认；执行要点不变：**正式 secret 必须重置**（沙箱 secret 已在提交历史暴露）+ 加密存储

### 阶段 1：正式环境准备（1~2 周，关键路径）

1. e签宝商务：正式版开通（D3 已确认预算）、**印章授权办理流程对接**（D2 逐家申请的入口/文书/时效）

   - **卡流巡检兜底任务**：定时扫描"签署中"超 48h 的流自动调 finish（防网络抖动卡单）
   - secret 加密存储改造（EncryptConfigLoader）
3. 配置侧：生产 SQL 准备（正式 host=openapi.esign.cn + 正式 appId/secret，SQL 模板已备好 14/15 号脚本的正式版变体）
4. **电子签在用模板量级盘点**：按近一年合同量拉 Top-N 模板清单（含公司/用量/关键字盘点），产出迁移优先级列表

### 阶段 2：试点公司生产切换 = 盘锦宜家（cid=43，部署 1 周 + 观察 1~2 周）

- 生产 jar 批次部署（esign/elecsign/communion/decoration/data 五 jar 同批，版本 8.3.030）+ SQL（配置行 + decorationcontract 列加长 SQL16）
- 宜家：企业实名认证 → 印章维护 → **印章授权办理（D2 第一家）**
- 1 个模板迁移落地：e签宝控制台重建该模板 + data.contract 加【e签宝】模板行（试点模板模式已演练过）
- **1~2 单真实小额合同**全流程试跑（生成→双签→归档→出证核验）
- 观察指标：签署成功率、回调到达率、归档及时率、客户投诉
- 通过标准：连续 2 周零事故 → 启动分批

### 阶段 3：分批推广（按模板迁移，批间观察 1 周，约 8~10 周）

**迁移原则**：模板按合同量从高频到长尾逐批迁移；印章授权按公司逐家办理（一次办理，该公司所有模板受益）。

**单模板迁移 SOP**（标准化，每模板 0.5 人天 + 试签）：
1. e签宝控制台重建模板（控件对齐前端 data 键，试点已演练）
2. `data.contract` 加【e签宝】模板行（path=`esign://docTemplate`，no=新 docTemplateId）
3. 老模板行视情况停用/并存（并存期员工两个都能选，各走各的厂商）
4. 试签 1 单验证 → 进观察

**单公司一次性动作**（每家 0.5~1 人天）：
1. 企业认证：印章维护 → authSignet/confirmSignet（orgId 写回，已闭环）
2. 印章授权办理（D2）
3. **回滚预案**（双粒度）：模板级——`data.contract` 行停用即回流法大大；公司级——路由 SQL 改回 `fadada` 即时生效。在途合同按合同记录的厂商继续走完（routeForRecord 已保证）

### 阶段 4：稳态收口（约 1 周）

- 高频模板迁移完成后：`elecsign.default.provider` = `esign`（新模板默认 e签宝）
- **法大大长期共存**：长尾低频模板留在法大大，不设清零 deadline；法大大合同量自然衰减后再评估降配/解约
- 首月月度对账：ERP 签署量 vs e签宝账单（计费核对）
