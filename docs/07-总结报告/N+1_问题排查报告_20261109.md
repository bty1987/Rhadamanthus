## 三、背景参考(不作为待办)

### 模式 B(646 处,启发式)

循环内 `.getBelonger()/getGoods()` 等链式访问命中 LAZY 关联 getter 名;**含 VO 同名误报**(VO 属性装配后链式访问不触库)。TOP 关联:Belonger(81)/Goods(51)/QuotationFunctionArea(34)。集中模块:quotation(90)/inventory(83)/decoration(82)。甄别方法:看接收者声明类型是 PO(真懒代理)还是 VO(误报)。

### 静态盲区

①`ptv`/`BeanUtil.copyProperties` 反射装配 LAZY 关联(列表转 VO 每行触发);②Struts JSON 序列化 VO 树触懒代理(先例:`pageSalesBalanceForPompany` 500)。量化需对 TOP 疑点接口开 SQL 日志实测。

## 四、修复姿势(后续治理基础设施)

| 场景 | 姿势 |
|---|---|
| **PagingQuery 分页查询**(新能力) | PO 嵌只读关联(`@ManyToOne LAZY` + `@JoinColumn(..., insertable=false, updatable=false)`) + `query.setFetchMode("关联属性名")`(core TopQuery 新增) |
| Criteria 查询 | 同上 PO 嵌入 + `criteria.setFetchMode(path, FetchMode.JOIN)` |
| 分表/继承映射 PO(如报价功能区项 PO0-4) | 现成 ids 批量查询 + Map(继承映射加关联有策略风险,务实例外) |
| 写操作循环(逐行 get+update) | 不修(行数少,操作型) |
