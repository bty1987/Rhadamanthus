# 客户保护规则业务说明文档

> **文档版本**: v1.0
> **创建日期**: 2026-04-11
> **相关模块**: customer 客户管理模块
> **核心类**: `CustomerProtectRuleServiceImpl`

---

## 1. 业务概述

客户保护规则用于保护装修订单的归属权，防止不同岗位的业务员之间互相抢单。系统根据配置的规则自动判断客户是否处于保护期内，如果在保护期内则需要通过审批流程才能变更归属。

### 核心价值
- 保护设计师/业务员的客户资源
- 防止恶意抢单行为
- 支持多种保护规则配置
- 与审批流程无缝集成

---

## 2. 规则类型

系统支持 **5 种保护规则类型**，定义在 `CustomerProtectRulePO.java`:

| type 值 | 常量名称 | 类型名称 | 起算时间字段 | 保护天数换算 | 适用状态 |
|---------|---------|---------|-------------|-------------|---------|
| `0` | `TYPE_AREA_INT` | 面积规则 | `measureTime` (量尺时间) | days ÷ 10000000 | 初始状态(0) |
| `1` | `TYPE_PAYMENT_ADVANCE_INT` | 预付款规则 | `depositTime` (定金时间) | days ÷ 1000000 | 已定金(1) |
| `2` | `TYPE_PAYMENT_DESIGN_INT` | 设计费规则 | `depositTime` (定金时间) | days ÷ 1000000 | 已定金(1) |
| `3` | `TYPE_DEPOSIT_INT` | 定金规则 | `depositTime` (定金时间) | days ÷ 1000000 | 已定金(1) |
| `4` | `TYPE_DUTY_INT` | 岗位规则 | `createTime` (创建时间) | days (直接使用) | 全部状态 |

### 保护天数存储说明
- **面积规则**: 存储值需要除以 10000000 得到实际天数
  - 例如: 存储值 300000000 → 实际保护天数 30 天
- **其他规则**: 存储值需要除以 1000000 得到实际天数
  - 例如: 存储值 30000000 → 实际保护天数 30 天

## 4. 审批流程

### 4.1 审批触发条件

当以下条件满足时，系统会触发归属变更审批流程：

| 触发场景 | 装修单状态 | 规则类型 | 起算时间 | 判断条件 |
|---------|-----------|---------|---------|---------|
| 面积保护期内 | 初始(0) | 面积规则 | 量尺时间 | 当前时间 - 量尺时间 < 保护天数 |
| 预付款保护期内 | 已定金(1) | 预付款规则 | 定金时间 | 当前时间 - 定金时间 < 保护天数 |
| 设计费保护期内 | 已定金(1) | 设计费规则 | 定金时间 | 当前时间 - 定金时间 < 保护天数 |

### 4.3 审批状态说明

| 状态值 | 常量名称 | 说明 |
|-------|---------|------|
| 0 | APPROVAL_STATUS_INIT_INT | 初始状态，审批已创建 |
| 1 | APPROVAL_STATUS_APPROVAL_INT | 审批中，等待审批人处理 |
| 3 | APPROVAL_STATUS_APPROVE_INT | 已同意，等待确认 |
| 5 | APPROVAL_STATUS_CONFIRM_INT | 待确认，等待发起人确认 |
| 6 | APPROVAL_STATUS_CONFIRMED_INT | 已确认，流程完成 |
| 7 | APPROVAL_STATUS_REJECT_INT | 已拒绝/客户拒绝 |

### 4.4 审批通过后的归属变更

```
审批通过 → approveForDecorationBelong() 执行以下操作:

1. 失效旧归属记录
   - 查询订单下该类型的所有有效归属记录
   - 将状态从 STATUS_INVALID_INT(0) 改为 STATUS_EFFCTIVE_INT(1)

2. 清空附加表字段
   - 设计师归属 → 清空 design/designDept/designRegion
   - 业务员归属 → 清空 sales/salesDept/salesRegion

3. 创建新归属记录
   - 根据 ApprovalDecorationBelongItemVO 列表创建归属记录
   - 设置归属人员、比例、部门、区域、业务类型等
   - 标记默认归属人员 (defaultFlag=1)

4. 更新订单主表
   - 如果 defaultFlag=1 且 type=0 → 更新 DecorationPO.designer
   - 如果 defaultFlag=1 且 type=1 → 更新 DecorationPO.salesman

5. 更新订单附加表
   - 更新 DecorationAdditionPO 的设计师/业务员信息
   - 更新 belongTime (归属变更时间)

6. 发送消息通知
   - 生成 MessageQueuingPO 消息队列数据
   - 事件类型: TEAM_DESIGNER_CHANGED / TEAM_SALESMAN_CHANGED
```

## 5. 关键业务规则

### 5.1 时间差计算

系统使用 `DateUtil.diffDay(Timestamp start, Timestamp end)` 计算时间差：

```java
// diffDay 返回 (end.getTime() - start.getTime()) / 一天的毫秒数
// 正确用法: diffDay(开始时间, 当前时间) → 得到经过的天数（正数）

// 示例
Timestamp startTime = decorationPO.getMeasureTime(); // 量尺时间
Timestamp now = DateUtil.getDateToTimestamp(new Date());
long daysPassed = DateUtil.diffDay(startTime, now); // 正确计算经过天数
```

### 5.2 规则匹配逻辑

- **区间匹配**: `value BETWEEN uppval AND lowval`
- **优先级**: 多个规则同时满足时，取剩余天数最多的规则
- **岗位规则特殊逻辑**: 同岗位抢单不触发保护

### 5.3 前端界面规则

| 类型 | 起始值字段 | 终止值字段 | 岗位字段 |
|------|-----------|-----------|---------|
| type ≤ 3 (面积/预付/设计/定金) | 显示 | 显示 | 隐藏 |
| type = 4 (岗位) | 隐藏 | 隐藏 | 显示 |

### 5.4 审批规则校验

| 校验项 | 说明 |
|-------|------|
| 重复提交检查 | 订单只能有一个进行中的归属审批 |
| 订单状态限制 | 已签订(签约/预签/复签/完工)的订单不可变更归属 |
| 归属类型限制 | 只支持设计师(0)和业务员(1)归属变更 |
| 比例校验 | 所有归属人员比例之和必须等于 1000 (100%) |
| 默认人员 | 必须有且仅有1个默认归属人员 |

## 8. 数据模型

### 8.1 CustomerProtectRulePO (保护规则表)

```java
@Entity
@Table(name = "customerProtectRule", catalog = "customer")
public class CustomerProtectRulePO {
    private long cprid;              // 规则ID
    private String title;             // 标题
    private short type;               // 类型: 0=面积, 1=预付, 2=设计, 3=定金, 4=岗位
    private int uppval;               // 起始值
    private int lowval;               // 终止值
    private DutyPO duty;              // 岗位 (type=4时使用)
```

### 10.2 常见问题

**Q: 为什么面积规则的保护天数要除以 10000000？**
A: 这是历史遗留的存储方式，面积规则使用更大的存储单位来避免与其他规则冲突。

**Q: 岗位规则的"同岗位不保护"是什么意思？**
A: 如果当前操作者的岗位与装修单业务员的岗位相同，不触发保护，允许直接抢单。这是为了避免同岗位内部的恶性竞争。

**Q: 审批接收人是谁？**
A: 当前实现中，审批接收人默认设置为抢单人自己，实际业务中可能需要配置上级主管作为审批人。
